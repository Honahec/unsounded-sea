# 沉钟之母：分件、绑定与巨兽动画设计

这篇文档解释当前方案的选择、运动原理与后续骨骼路线。通用资产生产和 LFS 操作见[模型全流程](MODEL_IMPORT_WORKFLOW.md)，运行时接入见[框架指南](FRAMEWORK.md#3d-战斗组合与扩展)，实测结果见[验证记录](FRAMEWORK_VALIDATION.md#沉钟之母-bang-分件与刚性动作流程)。来源、哈希和网格规格只维护在 manifest。

## 1. 当前到底使用哪一种绑定

**当前运行时是 BANG 分件后的刚性支点动画，没有柔性骨骼蒙皮。** 实际探索顺序是“整网格骨骼试验 → 大动作变形不合格 → BANG 分件 → 刚性支点与程序动画”。不能把它描述成“分件后已完成触手骨骼链绑定”。

| 路线 | 实际实现 | 状态与用途 |
| --- | --- | --- |
| 整网格 Generic Rig | Blender 自定义骨架、分区权重、烘焙动画，Unity Animator 播放 | 历史试验；大幅动作出现拉伸，未作为当前默认表现 |
| BANG 分件＋支点 | 身体、冠部、六条触手分别挂在 Transform 下；Unity 驱动刚性变换 | 当前使用；保持纹理和轮廓，支持抬起外端、拍下和小幅受击 |
| 分件后柔性触手骨骼链 | 根据实际触手中心线布骨、局部重拓扑与权重修整 | 后续方案，尚未制作或验收 |

支点能确定一个部件绕哪里运动，骨骼还可以通过蒙皮权重让部件内部弯曲。两者不能混为一谈。刚性部件也可以百分之百绑定到单根骨骼，但不会因此获得柔性变形；当前没有为这一等价效果增加骨架。

## 2. 从动作需求倒推分件

目标画面是远处约 208 m 高的巨兽与 18 m 调查船同框。攻击应读成“两侧触手缓慢离水、加速砸下”，而不是本体跳跃、全部触手同时开合。先确定运动职责，再决定切哪里：

- 身体承载整体重量；只有小幅蓄力、压沉和滞后的回稳。
- 冠部保留主要识别轮廓，攻击和受击时随身体整体运动，不独立甩动。
- 左右外侧两条粗触手承担攻击，其余触手维持低位，给画面保留稳定参照。
- 根部必须留在身体连接处；外端负责大行程。不能靠把整个部件向上平移来模拟抬手。

BANG 的职责是从已有模型拆出语义部件，不是自动提供可用关节、权重或动作。当前结果有多个壳片和独立触手，出处见 [BANG manifest](../ArtSource/Bosses/BellMother_BANG-manifest.json)。分件后仍需检查内侧封口、连接缝、部件归属、UV 与材质；仅有预览成功不能进入动画验收。

## 3. Blender：保留外观，建立可控制的层级

[制作脚本](../Tools/BellMotherBangBuild.py)在 `arch` 的 Blender 中完成以下处理：

1. 验证这份 BANG 输出的部件名称与数量，按已检查的语义分组；名称不匹配即停止，不能把编号当作空间方向。
2. 建立 `Body`、`Crown`、`Tentacle_01…06` 空物体，将网格挂到对应支点下。重新指定父节点时保留世界变换，避免模型突然移动。
3. 分件减面，保留原有材质和 UV，不再次生成整只怪物。减面只解决运行时预算，不等于获得适合弯折的拓扑。
4. 导出保留层级的 GLB。当前明确关闭 skins、animations 和 morph 导出，动作由 Unity 生成；面数、输出哈希及预览由 manifest 记录。

Blender 中的初始 pivot 是控制容器，**不是最终的解剖根部**。后续 Unity 根据触手实际几何烘焙根部和外端采样，修正“靠主体的一侧被抬起来”的问题。

材质问题与权重问题分开检查：静态姿态已错误时先查 UV、材质映射、法线和色彩空间；只有弯曲后才出错时，再检查拓扑和权重。换成骨骼不能自动修复贴图，增加贴图分辨率也不能修复蒙皮拉伸。

## 4. Unity：根部约束与外端方向

[导入与关节烘焙工具](../Tools/BellMotherBangSetup.cs)将基础表现模型归一化到 32 m，实际海面舞台再放大。身体、冠部和触手支点处于同一个父坐标系；计算局部位移时必须考虑这一层缩放，不能把模型局部数值直接解释成世界米数。

每条触手的采样方法：将其网格顶点变换到共同父空间，按与身体中心的水平距离排序，取最内侧与最外侧各约 5% 顶点的平均位置，分别作为根部与外端，再转换回部件局部坐标。平均采样比单个尖角顶点稳定，但仍只是几何估计；更换造型后必须人工检查，不能当成通用解剖识别器。

当前外侧攻击对为 `Tentacle_02/06`，选择依据是实际造型和战斗镜头，不是编号规则。对每条触手：

```text
向外方向 = 外端 − 根部（变换到共同父空间）
上抬轴   = normalize(cross(向外方向, up))
部件位置 = 随身体移动的根部锚点 − 新旋转 × 缩放后的局部根部
```

最后一行补偿旋转产生的平移，让根部始终留在锚点，抬起的是外端。左右触手分别计算轴，不共用一个正负角度猜方向；主体倾斜时，锚点、冠部和触手根部使用同一个身体变换。验收既检查外端高度，也检查根部误差与部件长度，避免“看起来抬了，但连接处已经移开”。

## 5. 动画的重量来自节奏与参照

当前实现位于 [BellMotherRigidMotion.cs](../Assets/UnsoundedSea/Runtime/Battle/BellMotherRigidMotion.cs)。不通过整体缩放制造弹性，也不把所有动作都做成同速正弦摆动。

### 攻击：慢抬、加速下砸、水阻制动、低位回收

| 阶段 | 当前时长 | 运动意图 |
| --- | --- | --- |
| 抬起 | 0.72 s | 外侧两条触手抬至约 46°，身体轻微蓄力 |
| 顶部延续 | 0.12 s | 继续微抬至约 48°，避免突然定格 |
| 下砸 | 0.28 s | 加速降至约 −6°，速度向触水集中 |
| 水下制动 | 0.12 s | 减速压至约 −10°，体现水阻 |
| 压住水面 | 0.18 s | 保持低位，不立即弹回 |
| 回收 | 0.62 s | 缓慢回到起始姿态 |

身体总运动保持克制，最低点比触手拍下晚约 120 ms，表现重量传递；冠部和根部共同跟随。其余四条触手只是小幅低位摆动，避免同时抬起削弱稳定感。角度只对当前支点和造型有效，新模型需重新标定。

### 受击：幅度可读，但不被小攻击掀飞

当前额外后仰上限 **0.8°**、侧倾 **0.18°**，下沉 **0.009 个支点父空间单位**。这三个量叠加在待机或攻击姿态上，不能直接当作整个模型的最终角度或世界位移。

受击用 0.32 s 建立压力、0.22 s 短暂压住，随后 1.26 s 缓慢回稳，总计 1.8 s。第一帧不跳到最大后仰；冠部和触手随同一小幅刚性变换承压，不分别甩动。连续受击从当前压力继续，幅度不无限叠加。每次计算基础动作前移除上一帧受击偏移，再叠加新偏移，因此不会累积漂移，也不重置待机相位或攻击时钟。

调节顺序是先确认首帧与回收连续，再调节幅度，最后看实际战斗距离下能否读出动作。本次仅小幅提高幅度，保留缓慢节奏；不重新引入 0.3 s 内大幅弹回的表现。

## 6. 动作、规则与海面的边界

`BattleDirector.Resolved` → `BattleActorView.Feedback` → 动作驱动。规则结算仍独立、确定；表现不能重新随机伤害。受击叠加不额外锁住整段出牌时间，攻击期间由舞台反馈锁防止重复打断。

拍水反馈由两条触手在下砸阶段进入 `BattleWater.SurfaceHeight` 时各触发一次 `SurfaceStruck`，不固定在动画结尾冒水花，也不把抬出水面算成拍击。浪向船传播后，船才随同一浪面采样升沉；具体波形、受控浮力与镜头配置以[海面配置](FRAMEWORK.md#海面配置)为准，不在本文重复参数。

## 7. 后续真正的骨骼绑定怎么做（未实现）

历史试验见 [BellMotherRig.py](../Tools/BellMotherRig.py) 和 [Rig manifest](../ArtSource/Bosses/BellMother_Rig-manifest.json)：曾建立 Generic 骨架，以空间分区和到骨段的距离分配权重，并烘焙多个动作。这个过程跑通了导出与导入，但不能证明权重美术质量；整块生成网格的相邻表面不一定属于同一运动部位，空间距离权重容易把身体与触手牵连。

后续建议在已确认的分件上逐步替换，先做一条外侧触手样例：

1. 沿真实触手中心线建立根部到尖端的骨骼链，根部挂到身体骨架；骨骼数量依据弯曲需求和画面距离确定，不照搬历史按方位估计的链。
2. 需要弯曲的段落补充合理截面与纵向拓扑，必要时重拓扑并重烘焙法线。纯减面后的不规则三角网不直接视为动画成品。
3. 根部权重保证连接，弯曲区域只在合理相邻骨段间平滑；壳片和冠部保持刚性绑定。逐条检查，避免另一侧触手或主体被跨部位权重拉动。
4. 先做抬起、压下、扭转三个静态压力姿势，检查体积、纹理拉伸、根部裂口，再制作完整攻击。第一版可用 FK；确有波浪式弯曲需求再增加样条控制器。
5. 沿用当前已确认的节奏，增加根部到尖端的延迟传递；幅度从小开始，不能靠快速摆动掩盖变形问题。
6. 导入 Unity Generic Rig，确认动画绑定路径与 Animator 所在根节点一致，根运动按舞台需求明确关闭或处理。先以独立候选 Prefab 对比当前刚性版，通过后再替换默认引用。

历史 [BellMotherAnimationSetup.cs](../Tools/BellMotherAnimationSetup.cs) 会覆盖默认 `BellMother.prefab`，不能为了试验骨骼直接运行它覆盖当前版本。新候选先改为独立输出路径。骨骼方案仍需保留触水采样、暂停和动作连续性契约，不能只验证 Blender 播放。

## 8. 复现与验收入口

已有模型只需打开 `SeaBossBattle.unity` 运行，无需重新生成。完整重做 BANG 低模需要原 BANG GLB；当前 Blender 脚本读取 `/tmp/BellMother_BANG.glb`，这个临时文件不保证存在，应从来源任务恢复并核验，不拿 LOD0 再次减面冒充母版。

- 重新减面与建层级：检查 `BellMotherBangBuild.py` 的工作站路径及输入，确认后在 `arch` 的 `~/Projects/unsounded-sea` 执行 `blender -b --python Tools/BellMotherBangBuild.py`。
- 重建当前表现 Prefab：退出 Play、检查现有编辑后，经 Unity CLI 执行 `BellMotherBangSetup.Build`。这会写 Prefab 和敌人引用。
- 只重新标定根部/外端：执行 `BellMotherBangSetup.UpdateAttackJoints`，不重建模型和材质。
- 只调动作幅度/曲线：编辑 `BellMotherRigidMotion.cs`，经 Unity CLI 重编译并确认完成，无需修改 GLB、Prefab 或 `.meta`。

```sh
unity command recompile --project-path "$PWD"
unity command recompile_status --project-path "$PWD"
# 确认编译完成后运行：
unity command run_tests --project-path "$PWD" -- \
  --mode editor --filter BellMotherAnimationTests --timeout 180
```

验收分开记录：静态外观 → 根部连接与长度 → 动作首帧/峰值/触水/回收 → 连续受击、受击接攻击与暂停 → 实际游戏镜头 → 目标设备性能。程序测试负责抓断根、跳帧和错误时序；画面采样负责判断可读性和重量感，二者不能相互代替。当前仍未完成柔性触手蒙皮、最终死亡演出、LOD1/2、独立 Player 与目标硬件性能验收。
