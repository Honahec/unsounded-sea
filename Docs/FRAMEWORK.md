# 基础框架开发指南

适用版本：Unity 6000.6.5f1 / URP。需求依据为 [概念设计](DESIGN_DOC_v0_1.md)。本文描述已实现的战斗基础、局外航海、扩展接口和存档契约；新增机制提案见 [机制与素材设计](ASSET_MECHANICS_DESIGN.md)。

## 快速运行

Editor 点击 Play 默认从 `Assets/UnsoundedSea/Scenes/MainMenu.unity` 启动，再选择「启航」或「继续航程」进入 `Voyage.unity`；有效未完航程需确认覆盖，终局记录不显示继续。`PlayModeEntry` 配置 `playModeStartScene`，不覆盖当前编辑场景；调试单场景时取消菜单 `Unsounded Sea > Play From Main Menu`，该偏好按本机项目保存。开局可选择医师或听音员，记住设备偏好。统一「调试选关」仅在 Editor／Development Build 显示，覆盖 25 个普通遭遇、八个 Boss／目标战与非战斗节点。旧 `Battle.unity` 与 `SampleScene.unity` 已退出构建，旧 HUD 组件及生成入口已清理；`ModelImportReview.unity` 仅供美术审阅；绑定资产保留集见[模型流程](MODEL_IMPORT_WORKFLOW.md)。

独立样例「雾海来客」：调查船上仅保留空潜水服「灯塔下的回声」，已移除蒙面祷告者。每回合 3 行动、抽 5 张牌；点击敌人切换查看对象，有目标牌拖到目标后松手，无目标牌上拖达到阈值后松手出牌，具体交互见下文。调查工具每场次数有限。额外遭遇牌「绘制封线」基础消耗 3 行动，每回合一次，累计 4 段获胜；它保留在手，不进入普通牌堆，敌人可以仍然存活。生命或理智归零失败。它是第一幕三个 Boss 候选之一。独立样例允许重开，航程战斗只允许保存后返回航海、继续当前战斗，不提供重试刷新资源。

第二场「沉钟海域」：船与「沉钟之母」中心相距约 260 m；32 m 基础模型通过舞台锚点放大至约 208 m 总高，下部浸入海面。斜侧外部镜头完整呈现 18 m 调查船，巨兽占据远处右侧和上方，二者之间留出海面动作空间。每轮公开巨浪（21 生命伤害）或钟鸣（11 理智冲击，可打断）；用格挡、理智防护或打断应对，撑过五轮后撤离。进度在敌方结算后推进，资源归零优先判败；不提供封线行动，伤害 Boss 不代替生存目标。

## 航海选路（局外）

场景切换统一经 `GameSceneLoader.Load` 异步执行，独立持久加载面板提供反馈，加载期间阻止快捷键、重复启动及战斗命令，完成后恢复后台加载优先级。`VoyageEncounterCatalog.MenuEntries` 只读取名称、分组和资源路径；`Resolve` 按需加载独立 `VoyageScenarioReference`。`AllEntries` 会加载全部遭遇，仅用于内容检查／模拟，不用于菜单。`VoyageEncounterLoadingSetup.Configure` 经 Editor API 生成独立引用资产，保留原 Scenario 路径和 GUID；航程内容同步后自动调用。标题菜单在进入时检查存档，点击新航程时重新核实覆盖条件；打开／关闭弹窗不重复回放存档。图鉴翻页不主动执行全局资源回收。

- **三幕标准航程（方案 A）**：海域仍为第一幕灰雾航道、第二幕尸骸之海／倒悬潮庭／无灯裂海三选一、第三幕无星深渊。各幕 Boss 独立按主种子抽取：第一幕为雾海来客／黑潮压舱者／空心航标，第二幕为 M02／M03／M04，第三幕为 M05／沉钟；第二幕海域选择不绑定 Boss。每幕 11 层，一条完整航线实际访问 11 个节点（含出发整备和幕末 Boss），全局 33 个节点；分支候选不是额外必经节点。主种子派生拓扑、布局、Boss、内容、可见性和战斗种子；调查与动画不推进规则随机数。
- **分支与合并**：起点两个出口，终点前一层单出口；中间层宽 2–3，普通连接至少两个出口，第 2→3、7→8 层按同分支配对单出口，避免交换顺序后重复访问同类节点。只连接相邻层，保留近邻几何约束。
- **节点节奏**：每幕仍有四场普通战、一场 Boss、一个事件、一个档案、一个独立奖励和三次整备。零基第 2/3 层的事件／战斗及第 7/8 层的档案／战斗按分支换序；第 6 层一条 `Perilous` 分支固定双敌，胜利后两次三选一。每条完整路径仍访问 11 节点，不登陆陆地。
- **知识边界**：开局只知道当前位置与两个出口，抵达后默认揭示最多两个后续出口，让已有分支直接可选；三出口节点保留第三条给旧海图，提前侦察保留。HUD 只读取 `KnownStops / KnownRoutes / Choices`，连节点的 `Next` 也过滤未知连接；不画隐藏地点灰点或完整拓扑。Boss 简报按本幕实际遭遇生成，不按海域名猜测；版本与兼容边界见「存档与复现」。
- **航行工具**：旧海图、测绘望远镜各每幕两次，分别补齐当前未知出口、侦察选定目的地再往前一段。无新信息或状态不允许时不扣次数；不占战斗槽、不因进入战斗刷新、不改地图与遭遇。
- **交互与动效**：默认中央为海面，右下航路列表显示地点、方向与耗时；选中后显示征兆和启航按钮，选择只预览，确认才出航。旧海图与远望收在海图下方，以文字和余次呈现；右上角文字按钮直接显示 M 海图、J 日志、B 行动簿、Esc 菜单，快捷键在根节点捕获，焦点位于按钮或滚动内容时仍可用，弹窗与文本输入保留各自限制。保留破损装饰字体，移除底部罗盘、航向针、圆形工具、启航印记与重复状态小字；累计小时和航段只在展开海图时显示。航图使用海流底纹、地点符号与弯曲虚线航路，不画隐藏拓扑；节点层间距以加长画布呈现，原生纵向 ScrollView 只滚动航图内容，打开时定位到当前航点，标题、图例、航行工具和关闭控件留在固定区域。调查船按所选目的地沿曲线实际转向、加速和减速；镜头从后斜侧跟随，滞后平滑转向且不随船体横滚。每段约 5 秒：前段出发地隐入浓雾，最后 2 秒目的地逐渐显现，抵达保留新位置与地点场景。减少动效改为约 0.25 秒淡化，在完全遮蔽时定位到终点；也支持途中开启。航行时收图；暂停／日志／设置冻结航段、海浪、船体、镜头和反射，展开海图也冻结环境，抵达只结算一次。
- **奖励与构筑**：新局固定 12 张不同牌；普通战后三选一、独立奖励四选一、险航两次三选一。公共／实际 Boss 奖励池保持机制过滤，普通次目标开放对应任务牌。`ClaimReward(cardId, replaceDeckCardId = null)` 可仅学习，或原位替换当前牌组一张；非法替换零修改，换出牌仍为已学。每次领取和替换写入历史；险航剩余次数与第二次候选通过回放恢复。幕末按下一幕实际 Boss 发奖，领奖后换幕；终幕直接结算。可放弃换 1 补给，无刷新。C076／C083 从第二幕池起投放。
- **事件、信息与资源**：`GameBalance` 统一生命 60、理智 30、补给上限 8，初始补给保留 3。五海域各三种事件模板，`EventTitle` 返回当前标题；航点名称与描述按类型匹配。医师 1 行动恢复 3 生命并获得 3 格挡；听音员 2 行动取得新声源后抽 1；罗盘匠在普通战查验可观察连接。船员同回合共享一次支援限制，查询不计调查牌新答案。档案、简报和跨战资源仍随历史恢复。
- **决策反馈与历史**：治疗只检查实际资源并显示禁用原因；没有新航路时禁止消耗抄录或标记。补给已满时放弃奖励明确无额外收益。相同整备配置不写历史，连续牌组／工具调整和航向预览合并为最终选择；出航、侦察或节点结算形成历史边界。终局显示资源、航迹、已学行动、消耗品和补给支出；死因仅使用已记录事实，不虚构致命攻击来源。
- **战斗边界**：目录解析 25 个普通遭遇和八场 Boss。普通航路按层分配单敌 variant 0–3，第 6 层险航分支使用 variant 4 双敌。非灰雾每海域两种节奏、三种隐匿；variant 3 的普通撤离／封线次目标允许击退或任务获胜。仅用 `VoyageCampaignSetup.SyncCombatBalance` 同步 `Plan(...)` 和现有敌人／遭遇数据，保留模型、场景与牌组引用，不运行 `Setup()`。`CardDeckPreparation.Apply` 注入真实航程资源和配装，Director 成功命令保存回放。
- **调试边界**：`VoyageSession.CreateDebug` 创建独立内存航点，禁止 `Export`；`VoyageRuntime.StartDebugEncounter / StartDebugNode` 复用真实战斗或航海 UI，`Checkpoint` 不写正式存档，胜利也不写永久证据档案。进入调试前若正式战斗有未保存进度，必须先成功保存；失败时保留原会话与错误，不能清空待保存记录。普通调试战仍有三选一结算，Boss 调试战直接结束，返回标题后可继续原正式航程。目录包含全部八场 Boss；`storm-gauntlet` 与 `hollow-beacon` 是新增规则通关入口，任意正常航程种子用于验证前两幕不重复分配。

`VoyageMapGenerator`／`VoyageSession` 属于纯 C# 航海规则；`VoyageRuntime` 负责场景边界与文件；`VoyageHud`／`VoyageSailingPresentation` 只负责交互和航行表现。`Voyage.unity` 已使用调查船与 Uber 海面，场景组合位于 `Art/Voyage/VoyageSeaStage.prefab`：嵌套引用 `SurveyVessel.prefab`，复用海面网格、天空和调色；独立 `VoyageOcean.mat` 降低常态浪强度，不传入巨兽扰流。船体采样同一 `BattleWater` 波形，限制俯仰／横滚；`VoyageWake` 在世界坐标保留弯曲尾流，并随波形更新、逐渐消散。

`VoyageSailingPath` 将已知图坐标按 3 m／单位映射到局部海域（北 = +Z），用上一段航向作为出发切线；这是航程过场，不是小时数对应的真实里程或自由驾驶。每幕保持相同局部坐标范围，换幕重定位到新起点，不沿三幕累加世界距离。扩展地图尺度时须同步扩展海面或加入浮动原点。`VoyageSailingPresentation` 的船、水、相机和偏移均可替换；运行时拥有材质实例、反射与尾流网格，切场景时释放。`Tools/VoyageOceanSetup.cs` 的 `Apply` 可经 Unity CLI 重建这一组合，拒绝 Play／未保存场景；它会覆盖航行表现 Prefab 与材质，已有手调先检查 diff。地点组合由独立的 `Tools/VoyageNodeSetup.cs` / `Build` 维护；不需要重建海面，尚无靠泊或登船动画。

`VoyageDestinationPresentation` 只实例化当前位置及确认出航后的目的地，按地点名查 `Art/Voyage/Nodes/VoyageScenes.asset`，不按战斗／事件类型猜外观，不读取隐藏拓扑。新增或改名地点须同步目录映射，漏配会告警。每项可单独换 Prefab、相对抵达航向的摆放与朝向。`VoyageSceneView` 控制整组渐显、灯光和浮动部件；材质使用 `Voyage Landmark` Shader 的雾色及细粒度覆盖渐变，读取 glTF RGB 法线。前 3 秒目的地不可见，后 2 秒从轮廓到完整材质；暂停冻结雾与节点，减少动效在遮罩内切换。退出时清理实例并恢复场景雾值。

漂浮残骸仅用于货船、渔船和潮流观测点，分别 3／4／9 组；采用非对称断口与不同宽厚、长短、倾角，在局部成组布置，保留空水面。碎片采样同一海浪的水平位移与升沉；暂停、减少动效均冻结。`RefineDebris` 仅重建这五个相关地点（含清空残骸的救生艇和浮标），并清理其废弃网格。

这是 14 种地点表现，不是 14 个独立战斗关卡。两个新增 Rodin 模型与复用船体、Editor 制作的设施组成场景，来源与预算见 [节点资产 manifest](../ArtSource/Landmarks/manifest.json)。

当前是可完成的三幕航程闭环，25 种普通敌人已使用独立骨骼模型和站桩战斗动作；不等于全部扩展系统交付。25 道具库存、装备被动和船员招聘已接通；候选独立剧情、自由移动动画与进一步持物／布料精修与五海域专属环境仍未完成。

## 3D 战斗组合与扩展

```text
BattleScenario（遭遇 + 场景 Prefab + 角色覆写 + 规则模块）
    → BattleDirector（独立 Session、选敌、命令、反馈锁、重开）
        → OceanBattleHud（BattleView → UI；Command → Director）
        → BattleStage（船体、相机、灯光、海面、音响、生成锚点）
            → BattleActorView（模型实例、碰撞选敌、名牌锚点、可选骨骼动作反馈）
```

- **换场景**：复制或创建带 `BattleStage` 的 Prefab，配置 `battleCamera`、`vessel`（所有随船运动的物体父节点）、`actorAnchors` 和选中材质，再替换 Scenario 的 `stagePrefab`。海面与音响可选；当前舞台不支持角色移动/导航。
- **镜头构图**：海面 Boss 的相机独立于船体 rig，船体横摇不带动镜头；巨浪来临时按前方水位预判升高并调整俯角，浪后回到基础构图。基础位置 `(85,22,-26)`、看向 `(0,8,70)`、垂直 FOV 60°。换船或海怪后需一起检查尺度、距离、海面覆盖、名牌和 HUD 遮挡，不能只移动相机。
- **甲板 / 海面锚点**：普通锚点保持甲板表现；海面锚点挂 `BattleAnchor` 并设为 `Sea`，必须放在船体 rig 之外，校验会拒绝错误挂载。设置独立位置、浸没深度、名牌高度/偏移、轻微升沉与扰流半径；海面角色通常关闭脚底选中环。碰撞范围按模型局部包围盒计算，锚点旋转/缩放不重复放大范围。
- **换角色**：修改 Enemy 的 `presentationPrefab`，或在 Scenario 的 `actorOverrides` 按敌人槽位覆写。模型约定脚底 y=0、正面 +Z、真实米制；锚点决定位置和朝向。同种敌人可以重复引用，规则实例 ID 为 `id:槽位`。出生前校验相机、船体、锚点和模型引用。
- **换遭遇**：Scenario 指向另一个 Encounter；牌组、资源、敌人意图和工具仍属于规则数据。UI 按快照更新，不依赖两只敌人的名字。新增敌人需增加相应舞台锚点并检查名牌排布。
- **特殊战入口**：派生 `BattleRuleModule`，为每次会话创建新的 `EffectRegistry` / `IEncounterObjective`。`SealingRuleModule` 用于雾海封线；`SurvivalRuleModule` 用于海面撤离，按已结算轮数计数。两者均不靠敌人全部死亡判胜。模块资产只存配置，不能共享可变进度。需要新命令、敌人阶段策略或即时玩法时仍需扩展 Core 与测试；当前入口不等于这些玩法已实现。
- **甲板骨骼动作**：`DeckActorMotion` 兼容保留集的两种骨名，缓存绑定姿态并按角色空间轴叠加脊柱／胸／颈／肩臂旋转；不使用海怪 Animator 状态名，不移动脚部和骨盆。七种动作家族、可调曲线与幅度见[机制文档](ASSET_MECHANICS_DESIGN.md#甲板敌人的战斗动作设计与当前实现)。`BattleView.ResolvedEnemyActions` 只包含上个成功 EndTurn 已执行的敌人行动（ID、通道、原始量），普通敌人和 Boss 召唤物按此播放；不解析日志、不读取新回合隐藏意图。`BattleDirector.Busy` 等待攻击／受击时钟结束，暂停时保持锁。海面巨兽同样消费该记录；表现不推进规则随机数。
- **动画资产接入**：`DeckAnimationSetup.Apply` 经 Editor API 更新 25 个 CuratedRigs Prefab、祷告者／空潜水服及敌人引用，不重建场景；要求退出 Play 并保存场景。会重新应用默认家族参数，并从 `Art/Models/DeckRigs` 重建 Prayer／Echo，手调前检查差异。原始绑定和模型来源见[模型流程](MODEL_IMPORT_WORKFLOW.md)。祷告者额外用 `PrayerSkirtMotion` 驱动八组裙摆骨骼，以强妖风表达攻击。甲板 `BattleStage` 使用缓入缓出的交战摇晃包络；海面战继续使用水面采样。蒙皮模型在出生时 BakeMesh 测量名牌／碰撞范围，运动包围盒不充当选取范围。
- **反馈事件**：Director 的 `Resolved(before, after, command)` 通知舞台，`Changed` 通知 UI；短暂反馈期间拒绝连点，规则仍同步确定性结算。暂停冻结舞台运动与环境声；减少动效关闭船体横移/倾斜、镜头震动和角色摆动，但保留随慢速水面的升沉与防淹没镜头升高。

「沉钟海域」使用 **Uber Stylized Water**：多向不规则涌浪、细波法线、半分辨率破碎倒影、浪尖/接触泡沫和海雾；深海材质关闭折射与岸边透明渐隐，浅深色均为不透明；甲板战也使用同一 Uber 水体与共享网格，独立 `DeckOcean.mat` 降低浪高。巨兽扰流与钟声只负责表现，不影响规则随机数。场景雾、月光、暖色船灯、Bloom/Vignette 构成海洋氛围；沉钟之母使用 BANG 拆出的 12 个刚性部件，由 `BellMotherRigidMotion` 播放短前摇、抬起触手、低位拍击、沉重命中和死亡动作。攻击时主体小幅上浮蓄力、拍下后下沉并延迟回稳，倾斜小于 1°；冠部和触手根部随同一躯干变换移动，保持相对连接。仅左右外侧两条粗触手（Prefab 的 `attackTentacles`，当前为 `Tentacle_02/06`）使用各自根部/外端采样点，缓慢抬起后加速下砸，触水后减速下压、低位停留，再缓慢回收；身体稍晚下沉，避免立即反弹。具体时序及采样见[验证记录](FRAMEWORK_VALIDATION.md#沉钟之母-bang-分件与刚性动作流程)；其余四条保持低位，不到 1° 的轻摆随回收淡出。禁止独立平移整段触手或按编号猜旋转方向。`SurfaceStruck` 在两条触手下落穿过 `BattleWater.SurfaceHeight` 时各触发一次，`BattleStage` 接入冲击浪与水花；不会把出水或动画末尾当成入水。攻击尚未结束时拒绝新命令，避免拍击被提前打断。受击以小幅共享变换叠加在当前动作上，不重置待机相位；冠部与触手保持连接，连续受击从当前压力继续，拍击不中断。分件与骨骼取舍、支点算法、动作曲线及后续方案见[沉钟之母动画设计](BELL_MOTHER_ANIMATION_DESIGN.md)。`BattleActorView` 的表现层只消费 `Resolved` 结果，规则仍独立结算；旧 Generic Rig 资产保留作回溯样例，没有骨骼的旧模型继续使用兼容的简化反馈。`BattleStage.placeholderCombatMotion` 只控制无动画模型的占位运动。

### 海面配置

- 普通战斗的 `FogSeaStage` 已接入 Uber 水面、半分辨率平面反射和 `StormSky`；重建 `OceanBattleSetup.Build` 后再运行 `Tools/DeckOceanSetup.cs` 的 `Apply`，单独更新该 Prefab／`DeckOcean.mat`，不改场景或航海／Boss 材质。近景基础浪高为 0.18／0.09 m，StormStrength 0.1，无巨兽扰流；保持甲板小幅摇晃与原镜头，避免直接继承巨浪振幅。暂停冻结水体时钟与反射，减少动效将水速降到 1/4；舞台关闭恢复先前天空盒。
- `BattleStage.water` 可选接入 `BattleWater`，`surface` 指向同一海面 Renderer；使用 `Art/SeaBoss/DeepOcean.mat` 和 `DeepOceanMesh.asset`。水面保持水平、单位缩放，放在 Water（4）层，反射层排除水面；一场战斗只启用一个平面反射水体。当前网格为固定战斗镜头设计，不是无限海洋。
- `BattleWater` 在每场开始克隆材质并创建反射组件，停用时恢复原材质、清理相机和 RT。`_SeaTime` 驱动全部水面动画，暂停冻结时钟及反射；减少动效时以 1/4 速率连续推进，不跳变相位。`_Threat` 负责常态巨兽扰流；每个水体独立维护最多 8 个有寿命的拍击波，`SeaImpactWave` 与 `BattleWaterWake.hlsl` 共用同一波形、时钟和来源参数，波峰、尾随波谷、法线与破碎泡沫一起向外传播。默认拍击振幅参数 80 m，宽度参数 70 m、传播速度 45 m/s，双触手叠加后平滑限幅至 110 m 以下；当前巨兽约 208 m 总高，近场浪峰按其 1/4–2/5 设计，远处逐渐衰减。材质不透明且关闭折射/岸边渐隐时启用 `_SeaZWrite`，避免浪墙内部前后面错误覆盖；高浪淡出平面倒影并使用环境反射。`SeaImpactSpray` 负责触水点的弹道水花与水雾，跟随水体时钟暂停并在解绑时清理；`Tools/SeaImpactSetup.cs` 只给现有舞台配置水花材质；其他巨兽可把自身入水事件接到 `BattleWater.EmitImpact`。避免直接修改共享材质。
- 常态海况由两组基础波与四组方向、尺度、速度各异的相位扰动涌浪组成；浪尖按噪声破碎，巨兽周围持续产生宽范围不对称扰流。`DeepOcean.mat` 的 Storm 参数可在材质 Inspector 调整，修改后重开战斗刷新船体采样。`vesselFollowsWater` 使用同一组波参数、扰流和拍击波采样船体中心、首尾及左右水位，`VesselWaveResponse` 用水面速度前馈与带阻尼的升沉/姿态响应保留惯性，避免快速涨水把船埋入浪中；冲击波到船处后才增加抬升、沿传播方向的有限横移和倾斜，常态目标俯仰限 6°、横摇限 9°，冲击期间目标上限为俯仰 24°／横摇 32°（阻尼响应可轻微超调）。换船后调整 `vesselSampleExtents`；这是受控浮动近似，没有 Rigidbody 碰撞、流体求解或倾覆模拟。暂停冻结海浪和船，减少动效收敛横移与倾斜，仍随 1/4 速海面升沉，恢复时平滑追随。
- `BattleWaterLighting.hlsl` 以水的约 2% 正入射反射率计算 GGX 高光，读取主光/Forward+ 点光的颜色、强度、衰减与阴影；法线像素方差抑制远处闪点。`Specular Tint` 为 0–1 色调，`Roughness` 控制展宽（有效 0.22–0.8），旧 Hardness/Size 不再使用。浪尖泡沫使用 `SurfFoam Color` 作为漫反射色覆盖水面，接受环境与直接光，不作自发光相加；接触泡沫仍为低亮度美术色。
- PC 管线需要 **Depth Texture / Opaque Texture**；当前 Unity 6000.6.5f1、URP 17.6、Forward+ 已配置。`reflectionScale` 默认 0.5，降低可减少额外渲染成本。移动管线、XR、多相机/多水位组合尚未验收。
- 上游版本、MIT 许可、原始哈希与本地补丁集中记录在 [UPSTREAM.json](../Assets/ThirdParty/UberStylizedWater/UPSTREAM.json)。只引入运行依赖，不依赖上游 Shader Graph 编辑插件。升级需重新应用时钟、风暴波形/法线/泡沫、光照、扰流和反射补丁，并验证所有 Shader pass；不要用上游重新导出的 Shader 直接覆盖本地版。

主页使用真实 `SurveyVessel` 与 `Lighthouse` Prefab，不再保留几何体占位背景或右侧圆形装饰。`Tools/MainMenuSceneSetup.Apply` 重建该背景：船位于右下、船头朝右上，灯塔位于右侧远景；`MainMenuSeaPresentation` 复用 `VoyageOcean` 材质与 `BattleWater` 时钟，使船随海面升沉，并遵守减少动效设置。灯塔来源见 `ArtSource/Landmarks/manifest.json`。

`OceanBattlePanel` 参考 1600×900；USS 位于 `Runtime/Battle/OceanBattleHud.uss`。中央保留 3D 画面，局内不显示章节与地点标题。左下显示生命／理智，格挡与防护仅在生效时显示；调查工具列于上方并保留余次／费用。左上显示目标进度，右下集中回合、行动与结束回合；结束回合复用 `SeaUiArt("seal")` 印记，按钮无额外黄色圆底，文字独立放在图案下方，右上常驻无边框「海图 / M」与「行动簿 / B」，J 打开日志。牌库／弃牌／消耗数量在手牌右侧及日志显示；Boss 特殊行动使用额外遭遇牌，不提供重复的任务按钮。字体使用项目 TextCore SDF，保留破损装饰字体与旧铜色细线。

手牌默认约一半藏于下沿，常态右牌覆盖左牌；`HandCardPresentation` 将选中牌置顶，悬停／聚焦牌再置于其上，同时抬起 150 像素、放大 10% 并摆正。间距按可用宽度与牌数持续收紧，不设导致溢出的最小间距；两端预留扇形旋转与预览空间，多牌在区域内完整横向显示，不改变纵向隐藏量。按钮命中区域稳定，显式 tabIndex 保持键盘顺序；窗口调整按逻辑手牌顺序重新定位，不受悬停置顶层级影响。不可用牌仍可查看精确规则、费用与消耗标记。新增手牌在反馈锁结束后按 35 ms 间隔滑入／淡入，其余手牌约 0.24 秒补位；普通重绘不重复抽牌动画。减少动效保留直接跟手与合法目标提示，关闭飞行、倾斜和入手位移。

鼠标／指针按下后移动至少 8 个面板像素才拿起卡牌，单击不出牌。`OceanBattleHud.Motion` 在根节点捕获指针，卡面脱离手牌裁切区域并平滑跟手。无目标牌不显示瞄准线：从按下点向上拖动不足 80 个 UI 像素后松手会回弹，达到 80 像素后松手立即出牌，不要求落在战场或玩家资源区。有目标牌才显示弯曲引导线与落点，松手时重新验证模型、脚下圆圈、信息区、机关或对应列表项；拖动期间不显示操作提示文字。无效落点、Esc、右键、失去窗口焦点和系统取消均回弹且不提交命令；暂停取消当前拖动。双目标牌先拖放第一目标，再把同一张牌拖向第二目标；再次拖向首个目标可按卡牌规则确认单体，第一步不付费。M05 的 `E05-01` 为无目标牌，随机召唤一名尚未召唤的守卫，不显示指向线或选择列表。手牌／弃牌／证据列表与盐格、继电器均是拖放目的地。

键盘仍可 Tab 聚焦后提交卡牌，再选目标；唯一合法敌人可由键盘直接提交。非拖动状态下点击敌人仍能查看，右键卡牌或 D 查看详情。海图／行动簿／暂停／结算弹窗禁用底层控件及根节点焦点，键盘留在当前弹窗；全局快捷键由根节点捕获。卡牌插画、常态卡面和手牌悬停／拖放沿用现有表现。理智条按实际最大值标出 12／5；状态徽记复用 `SeaUiArt`，快捷键复用 `KeyBadge`，术语提示统一由 `UiRules` 提供。

普通敌人名牌读取 `EnemyView.Style / Surge`，蓄势改变以短暂的前后数字反馈表示，减少动效时仍显示；当前声源／通道仅取当前选中敌人、本回合 `ScopeTurn` 证据。盐格与继电器从 `EncounterTargetView.State / MeasuredValue / IsSeal / IsCurrent` 绘制公开图形，未知格没有危险答案；机关按钮仍使用当前牌实际合法目标。Boss 状态行保留阶段与限制，目标进度只在左上显示。

`BattleMotionLayer` 只消费 `Resolved` 的公开前后快照：枪击短轨迹／近战划击、伤害数字、格挡／理智防护刻线、调查确认、治疗与目标推进反馈。卡面释放后约 0.5 秒缩入弃牌位置，消耗牌向上消散，保留的遭遇牌回到手牌；血条约 0.32 秒缓动，行动数字轻微放大后恢复。结束回合先显示敌方行动，反馈锁结束后显示新回合。动效层跨 HUD 重绘保留，暂停冻结，退场释放临时元素；不读取隐藏意图、不推进规则随机数、不在动画回调中执行命令。图形使用矢量刻线与既有插画，没有新增图片或模型。

共享 `UiMotion` 为主菜单、图鉴、设置、航海清单、奖励、战斗行动簿和主要弹窗提供约 0.2 秒入场、0.12 秒退场淡化；退场元素不接收指针与焦点，按钮有悬停／按下过渡。动画完成只调整表现属性，不重建业务状态。减少动效跳过这些过渡；既有航行及骨骼动画继续由各自时钟管理。

敌人信息按战斗相机视口和 UI 根节点换算，不依赖反射渲染期间的 `Screen` 尺寸；普通双敌按屏幕左右位置，将姓名、生命与意图分别放在两侧外缘，避开模型，以无边框 UI 同时显示。单敌信息放在左侧；Boss 本体与封线目标战放在上方中央偏左的留白区域；唱诗匣、盐格与继电器占用左侧时（M02–M04），召唤单位统一列在右侧。随三维锚点移动的机关标签会被限制在屏幕内并互相错开。共享 `EnemyIntentDetails` 将征兆按分号换行，省去“可能行动”等标题，生命伤害与理智冲击使用心脏／眼睛图标，数值不带“点”，“可打断”显示为小标签；已确认不攻击（含 M05 守卫召唤当回合、空转回合）不显示意图，未确认候选中的不攻击行动只显示名称；未确认的多候选仍显示全部可能行为，不提前泄露真实分支。仅有一个可能意图的敌人从锁定起即视为已确认，条件伤害、抽牌与已确认目标规则共享这一状态。历史调查按需查日志。

`BattleDirector.ViewRevision` 仅在规则成功结算或重开时递增；动作解锁只刷新按钮可操作性，不重建 HUD、不闪烁禁用色。状态重建保留可恢复焦点与手牌、工具、日志滚动位置。日志可滚动查看完整可见历史，不再截断为最后 12 条。调查工具使用规则快照 `ToolView.Enabled / DisabledReason / Targets`，工具区域短句标明聚焦目标，已回答问题直接禁用。


`MainMenu` 与 `SettingsPanel` 共用深墨绿、旧黄铜与象牙文字样式；Esc 打开简短暂停菜单，J 单独打开航海日志。覆盖存档警告、放弃后果和错误不省略。设置提供总音量、音乐／环境声、音效、1280×720／1600×900／1920×1080、显示模式、垂直同步与减少动效；音量百分比固定留宽且不换行，设置内容可滚动。`GameSettings` 属于设备偏好，不进入规则或回放。旧 `BattleHud.cs / .uss` 和对应 meta 已删除；清理入口 `Tools/UiExperienceSetup.cs` 先检查依赖及未保存场景。

四个 UI 入口通过 `UiFont` 从现有中文源字体创建共用的运行时动态 SDF 字体，保留采样尺寸、图集尺寸和渲染模式。新增字形只填入运行时图集，不修改导入的 `default_zh.asset`；切场景复用，新的 Play 会话重置缓存。不要通过恢复正在使用的字体资产来清理字形缓存，这可能让 TextCore 已缓存的字形失去图集引用。

场景已入库，无需生成脚本才能运行。需要有意重建本场样例时，用 Unity CLI 执行 `Tools/OceanBattleSetup.cs` 的 `OceanBattleSetup.Build`；它会覆盖本场场景与配置，但保留航海标题入口，运行前先保存改动。`Tools/SeaBossSetup.cs` 的 `ImportModel` / `Build` 分别归一化 Boss 并重建海面样例；仅重设海面战构图可调用 `SeaBossSetup.ApplyComposition`，不会重建遭遇或场景。重建后再执行 `Tools/UberWaterSetup.cs` 的 `UberWaterSetup.Build` 恢复新版海面（只更新水体、雾和相应 Prefab 配置）。`Tools/ImportSurveyVessel.cs` 负责选定船体版本的归一化；模型制作和 LFS 规范见 [模型全流程](MODEL_IMPORT_WORKFLOW.md)。

### 八场 Boss／目标战

M02–M05、雾海来客、沉钟、黑潮压舱者与空心航标均由开发调试入口调用目录中的同一 Scenario。各幕候选范围见「航海选路」；海域影响普通遭遇与物资主题，针对卡牌奖励、补给与简报跟随实际 Boss。M02–M05 每场使用独立 Encounter 和舞台 Prefab；机制设计主出处为 [扩展设计](CONTENT_EXPANSION_DESIGN.md#b02b05-共用遭遇牌契约)。

- `BossRuleModule.bossKind` 选择 `BossEncounterKind`；`BattleScenario.CreateSession` 注入 Core 的 `BossEncounterRules`，每次重开创建独立状态。M02 为唱序封匣／击破发声囊，M03 为盐格封栓，M04 为继电器／闸锁／输出窗口；M05 由常驻 `E05-01` 逐名召唤五名守卫，击退全部守卫即胜利。
- M02 首回合自动公开第一条唱序约束，第二回合自动补齐第二条；聆听只提前取得尚未知的约束，完整后移除，不重复收费。潮囊治疗实时更新伤害进度，并记录独立治疗动作。M03 对已验算可解底图按种子施加八种对称变换，同步转换危险格、初始公开格与封栓；不是任意雷区生成器。M04 第一阶段通过既有状态栏和机关提示公开 R1 正接／R2 反接，正确数量仍显示为进度；完成后明确提示下一回合开闸。M05 不再包含建绳、关闭航标或撤离阶段。
- 首回合正常抽牌后授予稳定实例的遭遇牌；保留在手、不进入普通牌堆，阶段和每回合次数通过 `CardView.Enabled / DisabledReason / Targets` 公开。出牌仍使用 `BattleCommand.Play`；无目标的聆听与随机召唤立即执行，有目标牌选牌后选择目标，确认前不扣费，Esc／右键取消。
- 封线目标使用遭遇牌 `E01-01`「绘制封线」，保留在手，基础费用 3 行动，支持既有折扣，每回合一次。回声循环 20 生命重击与 10 理智施术，只有后者可打断；玩家需要安排防护与任务回合。旧 `AdvanceObjective` 仍供同版本回放使用，不由 HUD 按钮发出。
- `BattleView.EncounterTargets` 只含公开机关状态；盐格危险位置不直接暴露。`EnemyView.Targetable` 区分可攻击单位和规则本体。M05 本体不可选中，五名守卫开场休眠，玩家使用 `E05-01` 后从尚未召唤者中按战斗种子随机选一名永久入场；没有自动召唤，不会重复抽中已召唤者。
- `BossTargetAnchor` 连接场景机关与 HUD。M03 使用可读的 4×4 盐格盘；M04 只在选牌后展示对应极性／闸锁目标。M05 随机召唤不提供目标选择或绕过遭遇牌的额外机关操作栏。

四个舞台复用 `DrownedBellStage` 的 Uber 水面、调查船与同相位随浪运动，采用各自构图。M02 本体悬浮于海面上方；M03 本体使用独立海面锚点；M04 的执旗者由漂流旗舰舰艏承托，下身收于破船结构中，与舰体共享运动支点，不再从水下入场；M05 沿船身中轴正面构图：调查船船头朝前，本体立于正前方；四名侧翼守卫约为本体四成高，靠船左右两名向外展开；中央钟守卫位于船与本体之间，约为本体三分之一高，只遮挡本体下部。意图信息分置两侧留白，中央守卫信息放在左下空隙。`Tools/GiantBossSetup.BuildM05` 只配置 M05 本体、守卫引用和该构图，要求五份守卫 Prefab 均已导入。本体与守卫从即时海面以下升起。敌方回合先逐名执行存活守卫行动，最后本体释放随回合递增的理智冲击，曲线见 [B05 契约](CONTENT_EXPANSION_DESIGN.md#86-b05无星王座的守望者召唤五守卫)。每次命中同步显示该次真实结算后的资源数字、条和飘字，不能提前显示整个回合的总伤害。冷蓝光在本体周围聚集后迅速汇向调查船；验收范围见[验证记录](FRAMEWORK_VALIDATION.md#m05主菜单模型与分幕-boss-池)。

### M02–M05 巨兽骨骼表现

`GiantBossRig.py` 将 BANG 部件绑定到真实骨骼，`GiantBossSetup.Build` 配置表现 Prefab 与现有四个舞台；原始 PBR 图片不改。`BossAtmosphereSetup.Apply`（Editor 命名空间）为四场绑定独立 `StormSky` 材质和预烘焙环境反射，并由 `BattleEnvironmentLighting` 在退出时恢复入口的环境光与反射。覆写材质沿用 GLB 当前导入材质的外部压缩贴图，仅校正骨质／膜体／盔甲的金属度与法线强度，资产集中在 `Art/Bosses/Atmosphere`；不修改全局 glTF Shader。此工具只调整 M02 飞行构图，保留 M03–M05 已有机位与槽位；`GiantBossSetup.Build/BuildM05` 已调用相应收尾配置。制作和导入顺序见[模型流程](MODEL_IMPORT_WORKFLOW.md#m02m05bang-分件后的解剖绑定)，不同于沉钟之母的刚性 pivot 实现。

| Boss | 绑定与动作重点 | 战斗反馈 |
| --- | --- | --- |
| 骸潮领唱者 | 身体／头颈／声囊，左右鳍与尾端；悬空侧身朝船，缓慢升沉；声囊蓄势、头颈小幅前压，鳍尾滞后回稳 | 声囊蓄势后从嘴部释放三道空气压力环直接命中船，不产生攻击海浪；召唤只产生声囊雾流 |
| 倒悬司衡者 | 主体与双拱保持硬质轮廓，下方悬摆和垂饰缓慢拖动 | 物理攻击释放朝船推进的螺旋风流，不发攻击海浪；理智仪式保留雾流 |
| 无灯执旗者 | 先收杆，再将实际旗杆端点转向船并前刺，旗布随三级骨链滞后 | 旗杆端点在释放时到达船体，产生局部碎屑；不发攻击海浪，理智号令保留独立共鸣姿态 |
| 无星守望者 | 外框独立，头部微动，左右帷幕短链展开 | 守卫先逐名行动，本体最后释放随回合递增的理智脉冲；五名守卫由牌逐名召唤并从水下升起；击退全部守卫结束战斗，不表现杀死本体 |

`BattleActorView.Update` 同一时钟驱动 `GiantBossMotion`，先同步暂停再更新。待机相位持续推进；攻击在约前 46% 蓄势，57% 达到主要释放姿态，余下时间低位停留并回稳；滞后链单独延迟。受击约 0.28 秒承压、1.9 秒回稳，叠加当前姿态，连续受击不清零；不移动整个 Actor 根节点，不使用弹簧缩放表现重量。减少动效同步缩小旋转、平移和囊体起伏。

M02–M04 的仪式采用展开／抬起的持续共鸣姿态，召唤采用持续呼唤曲线，区别于物理攻击；均不产生物理冲击浪。M03 的 `BossWindEffect` 以七条三维风带推进，沿骨骼同一时钟冻结与回收；专用 Shader 放在 `Art/Shaders/Resources/BossWind.shader`，通过 Resources 显式加载并带入构建。M04 用真实杆端与船上目标计算朝向和有限躯干收放，不平移 Actor 根节点。`FlagshipPresentation` 在骨骼更新前驱动舰体缓慢起伏／倾侧，随后更新四根环链；施力与受击在舰艏产生木尘。继电器与三锁锚点随残舰移动，第三阶段按公开状态熄灭旗坛护持；暂停冻结整组表现，减少动效关闭舰体摇摆。这是有界的表现运动，不是刚体船舶或链条物理求解。`BossTargetAnchor` 只消费公开机关状态，以实例材质属性和唱诗匣共鸣管的收拢反馈关闭、测读、危险停用、当前极性及已释放闸锁；暂停冻结管件，减少动效直接显示终态，停用恢复原姿态与属性，不修改共享材质。`Tools/BossPresentationSetup.cs` 的 `Apply` 更新三场既有补光，并调用 `UnsoundedSea.Editor.UnlitFlagshipSetup.Apply` 重建 M04 残舰装饰与斜侧构图；该入口保留机关 ID，不改遭遇规则。`GiantBossSetup.Build` 也会重新应用旗舰布局；只修改 M04 时使用专用入口，避免重设其他 Boss。三场的免费信息／致死停止契约加入各自内容指纹，旧 M02–M04 战斗回放拒绝恢复，其他遭遇指纹不变。

`OceanBattleHud.Bosses` 仅在 M02／M03／M04 生成固定左侧机关区：三只唱诗匣集中显示名称与关闭状态；盐格按 4×4 排列并显示坐标，右键或 F 切换个人标记；M04 分组显示两座继电器的三态端子、当前接线及三锁条件和已释放状态。仍由遭遇牌选择或拖放目标，机关本身不绕过卡牌付费。标记仅保存在当前战斗视图，不付款、不提交命令、不成为证据，不改变安全格推理；重开或离开战斗清空。所有新样式由三场专属根类限定，普通战、M05、沉钟及战斗外 UI 不应用。

`ResolvedEnemyActions` 决定是否播放及物理／仪式／召唤／治疗类型，不能直接读取下一回合意图。M03／M05 不可直接攻击的本体，只按规则事件反馈；M05 的本体理智行动触发蓝色精神脉冲。M02 的 `BossSonicEffect` 从随头骨运动的 `sonicOrigin` 嘴部锚点沿空中路径向船释放压力环，发声囊继续承担蓄势与召唤雾流，首道约 0.8 秒抵达；关闭水下入场和巨兽扰流水域，不走 `BattleWater.EmitImpact`。`BossAtmosphereSetup.ConfigureChoirDeck / ConfigureChoirMouth` 可独立修正 M02 左侧前甲板构图、召唤锚点、随船补光和嘴部锚点，不重烘环境或改动其他 Boss。M03／M04 分别走风压／旗杆接触反馈。`GiantBossEffects` 提供局部盐雾、蓄势雾和朝船行进的仪式脉冲，不额外结算伤害。M02–M04 敌方行动也沿用逐次命中表现：声压／风压／直刺在接触船体后更新该次真实资源值，整段行动完成前保留旧回合意图，避免提前显示下一回合和总伤害。巨兽攻击与退场期间 `BattleDirector.Busy` 阻止命令抢断，暂停同时冻结骨骼、粒子、风带与水体。



## 层级与依赖

```text
UnsoundedSea.Core                 纯 C#；无 UnityEngine 引用
    ↑
UnsoundedSea.Runtime              ScriptableObject、UI Toolkit、文件存档适配器
    ↑
UnsoundedSea.Editor               内容校验、幂等样例初始化

UnsoundedSea.Tests.EditMode       NUnit 行为测试，引用 Core / Runtime
```

规则层不读取场景、时间、全局随机数或静态单例。每个 `BattleSession` 独立持有牌堆、资源、敌人、知识和操作记录，可以同时运行多个会话。外部依赖通过构造函数注入，不引入服务定位器或全局事件总线。

- `Definitions.cs`：不可变战斗规格。构造时复制集合；Unity 资产只负责创作静态数据。
- `BattleSession`：命令入口、回合状态机及规则协调；所有玩家操作调用 `Execute`。
- `BattleView`：只读快照，UI 不持有可变规则状态。敌人的真实行动只存在于 Session 私有状态中。
- `CardCatalog` / `BattleCardRules`：96 张正式目录卡的规格、合法目标、费用与效果；`EffectRegistry` / `ICardEffectHandler` 保留通用效果和自定义遭遇扩展入口。
- `CardSpec.Category / RequiresTarget / HasFallback / BossIds` 与 `ItemSpec.BossIds` 是表现层可读元数据；资产构建缺省按规范 ID／效果 ID 取得目录元数据，不改既有卡牌身份。元数据不进入战斗内容指纹，分类与目标规则不再维护 `LegacyCardNumbers`。
- `EnemyView.Style / Surge` 和 `VoyageSession.PreviewStyle(stop)` 提供公开策略及升压徽记；不读取锁定随机分支。
- `KnowledgeState`：证据带来源和可信级别，低级别记录不能覆盖已验证信息。
- `IEncounterObjective`：击退、封门、存活目标；可注入其他目标实现。
- `RunMap`：有向无环节点图，区分进入与完成节点，阻止跳点、回访、悬空连接和不可达节点。
- `BattleReplay` / `IBattleSaveStore`：规则回放与存储介质分离。
- `BattleDirector` / `BattleScenario`：运行时组合入口与可替换配置；`OceanBattleHud` 仅负责表现。

## 保证的规则

1. `TurnStart → IntentLocked → PlayerTurn → Resolve → TurnEnd`；终局进入 `Victory / Defeat` 后拒绝新操作。
2. 每回合重置行动、格挡和理智防护，默认抽 5、行动 3。手牌在结束回合进入弃牌堆；抽牌堆耗尽才洗入弃牌堆。
3. 卡牌拥有唯一实例 ID。出牌期间先离开手牌，效果结算后才进弃牌/消耗区，因此抽牌效果不能立即抽回自身。
4. 先验证费用、目标和可用性，再修改状态；失败命令不写入回放。效果处理器是受信任规则代码，应保持确定性、无异常、无外部 IO；目前没有针对自定义处理器异常的事务回滚。
5. 敌人行动在玩家回合前锁定。抽牌与敌方行动使用分离的固定算法随机序列；调查不访问随机数。两候选异常敌人共享征兆，而调查仅修改可见知识。
6. 提灯确认可观察动作；听筒只回答声源；贝壳只回答伤害资源类型。不可观察或已回答的问题不消耗道具。每场工具使用次数重置，最多装备两个不同道具。
7. 本回合意图确认在下回合失效；历史证据保留，键中包含目标和回合。日志只记录当时玩家可知信息，真实行动直到调查允许或实际结算时才显示。
8. 格挡仅减生命伤害，理智防护仅减被动冲击。主动支付绕过防护，并要求支付后至少剩 1 理智。耗尽生命或理智立即失败。
9. 封门任务独立于手牌，每回合最多一次、消耗 1 行动。击杀不自动完成封门/存活目标。存活目标在敌方结算后计数，资源耗尽优先失败。
10. `exhaust` 按实例计数；消耗牌本场不再洗回。C085 另有本回合同名限一次规则。保留按实例结算，到回合边界清除指定，不能让已打出的牌在后来洗回时继续保留。

## 新增内容

### 新卡牌

完整目录以 `Core/CardCatalog.cs` 为数据主出处，C001–C096 为稳定目录／效果号，既有十个内容 ID 保持不变。修改目录后通过 Unity CLI `run_script --file Tools/CardCatalogSetup.cs --entry CardCatalogSetup.Build` 同步 96 份 `Content/Cards/*.asset`、配置插画导入并校验；不会重建场景或替换既有 GUID。目录之外的遭遇卡仍可通过 **Create → Unsounded Sea → Card** 创建，使用通用效果或自定义处理器。

标题菜单图鉴只读浏览全部 96 张卡牌与完整卡面，不再编辑初始构筑。`CardCatalog.Starter` 是固定 12 张不同初始牌的唯一来源，旧自选牌组偏好不再读取；航程内仍可在整备点把已获得方案编入 12 张行动牌。`CardDeckPreparation` 只在游戏入口应用：主线 `BattleDirector` 调用 `CreateSession(..., usePreparedDeck: true)`；`EncounterDefinition.Build()` 保持纯内容构建，不读取玩家偏好。已验证战斗证据在胜利后归档，后续只注入对应敌人的档案。

96 张目录卡与 10 张 Boss／封线遭遇牌均有独立生成的 `Resources/CardArt/<稳定卡牌ID>.png` 背景，统一海洋哥特、旧黄铜暖光与冷蓝阴影。`IllustratedCard` 在主线和行动簿复用：整幅插画铺满卡面，左上行动费用独立显示；标题与简短效果句限制在卡面下方 66% 的内缩阴影区，不把规则解释铺满插画。`CardCatalog.FaceDescription` 维护人工精简文案，完整 `Description` 留在提示中；必要条件、主动支付与消耗不能省略。模型、提示词、来源与文件哈希集中在 [插画 manifest](../ArtSource/Cards/manifest.json)。

不可用卡牌不显示禁用原因；点击尝试出牌后，失败原因作为 2.5 秒字幕显示，右键／D 仍可查看完整卡面。遭遇牌费用只显示实际行动消耗，包括合法折扣；绘制封线基础消耗 3 行动。航程战胜利在动作反馈结束后自动返回航海，不弹胜利页；保存失败时留在战斗并提供重试保存，避免丢失结算。

滚动条统一复用 `GameMenu.uss` 的原生 ScrollView 样式：墨绿轨道、旧黄铜滑块和箭头、象牙色焦点；行动簿、航海日志及战斗 HUD 共用。保留原生内容区滚轮、拖动、键盘和自动显隐；`ScrollWheel` 将面板留白上的滚轮送入该页纵向滚动条，避免鼠标必须压住滑块。行动簿详情宽度包含轨道留白。船上清单整备页显示当前航点与物资／工具／装备槽位，行装页将携带、放回、装备操作合入对应物品卡，完整效果在悬停／焦点详情显示；档案按海域情报、本次航程与过往见闻分组，不显示内部标识。`VoyageNodeChoice.DisabledReason` 提供配装和服务的实际禁用原因，仅供显示，不改变合法性判断或回放格式。

选目标统一使用 `CardView.Targets` 的稳定 ID；零选择牌传 `null`，失效选项在付款前拒绝。C054 先支付并打出，再通过 `BattleView.PendingChoice` 公开最多三张牌的完整排列；期间阻止其他命令，必须用 `BattleCommand.Reorder` 完成，零行动仍可选择，不能取消退款。确认排序后只抽一张，空抽牌堆禁用且查看不洗牌；两条命令均进入回放。C063 与 Boss 常驻继电器共享调整次数，C044 共享开格额度；其他场景的替代收益不绕过当前场景已有机制的次数或证据门槛。

卡牌联动由 `BattleSession` 保存三个独立状态：本回合调查牌实际取得新答案的目标集合、实际跨过上一回合弃牌边界的保留实例集合、按目标记录正伤害武装实例的集合。C002／C050 仍要求意图已确认；工具和船员查询不加入第一集合。C014 出牌时消费保留标记，回收不能复用；C016 必须找到其他实例的命中，零伤害不计。全部通过成功命令重放重建，不另存可变状态快照。

修改数值后经 Unity CLI 执行 `Tools/CombatBalanceSync.cs`，调用 `CombatBalanceSetup.Sync` 同步卡牌、普通敌人、独立随行配置和 Boss 资源；该入口拒绝 Play Mode 与未保存内容资产，不重建场景／模型。普通敌人数值主出处是 `VoyageCampaignSetup.Plans`，Boss 资源规格在 `CombatBalanceSetup`，阶段攻击在 `BossEncounterRules`；`BossExpansionSetup` 复用资源规格，B02／B04 进度上限读取实际 EnemySpec 血量。验证入口与当前限制见[验证记录](FRAMEWORK_VALIDATION.md#卡牌联动与敌人数值)。

通用扩展效果（目录卡另外注册 `c001`–`c096`，具体结算见 `BattleCardRules`）：

| ID | 参数与含义 |
| --- | --- |
| `damage` | 对所选敌人造成 amount 伤害 |
| `block` / `ward` | 获得 amount 格挡 / 理智防护 |
| `draw` / `heal` | 抽 amount 张 / 恢复 amount 生命 |
| `observe` | 记录可见征兆；amount 不使用 |
| `investigate` | 提灯式调查，意图已知则抽 1；amount 不使用 |
| `conditional-damage` | 已确认时造成 amount 伤害，否则 5 |
| `interrupt` | 打断本回合可中断动作；amount 不使用 |
| `objective` | 推进允许任务行动的目标 amount 点 |

新规则实现 `ICardEffectHandler`，在组合入口创建默认注册表后调用 `Register("your-effect", handler)`，传给 Session。处理器通过 `EffectContext` 执行动作，保持无状态、确定性；不要直接操作 Unity 对象。`conditional-damage` 的未知伤害 5 是当前样例规则；如需通用多参数效果，应扩展 `EffectSpec` 并同步内容指纹和版本，而非用卡牌 ID 分支。

### 新敌人和遭遇

创建 Enemy 和 Encounter 资产。灰雾普通战保留原循环；第二、三幕每区 variant 0/3 为节奏型，开局按规则 RNG 随机一次起点，之后固定循环并公开当前行动；1/2/4 为每回合随机的隐匿型，共同征兆不泄露分支，候选生命在前、理智在后。第 4 个敌方回合起正伤害 +2，随后每回合 +1；零伤害始终为零，公开 `Surge` 不因真实分支变化。通道减伤作用于增幅后数值，候选与确认／证据／日志／结算一致。非灰雾 variant 3 目标为撤离 3（尸骸／深渊）或封线 3（潮庭／裂海），完成目标或击退全敌获胜；不改变 Boss 阶段规则。

同一敌人资产可在遭遇中多次引用，编译时按资产 ID 和下标生成不同实例 ID。`presentationPrefab` 是表现接入点；新 `BattleStage` 会实例化该字段或 Scenario 覆写。已绑定样例、独立审阅场景和生产流程见 [模型全流程](MODEL_IMPORT_WORKFLOW.md)。

自定义目标实现 `IEncounterObjective` 并注入 Session；恢复回放时必须注入同样的目标与效果注册表。当前资产菜单提供击退、封门和存活三种配置。

### 更换界面

生产 UI 可以使用 uGUI 或 UI Toolkit，只需读取 `session.View`，提交 `BattleCommand.Play / Investigate / Task / EndTurn` 并处理 `CommandResult`。不要从敌人配置和随机种子反推当前隐藏意图。快照会复制集合，适合按命令刷新，不应每帧轮询分配。


`SupportCatalog` 定义 25 道具和 10 船员；`BattleLoadout` 校验最多两份战斗物资、三件不同装备且最多一个引擎、航标和被注视。`BattleSupportRules` 处理 `UseConsumable`、船员、装备触发与显式证据组合；`BattleView.SupplyActions` 提供合法目标。所有扣费先验证，消耗记录在 `SpentConsumables`；每次成功战斗命令写回待续回放，战后由 `ResolveEncounter` 验证携带份数并一次扣库存。装备、受伤与类型化证据均进入回放指纹。

节点主面板将 `GetNodeChoices` 的互斥「本节点选项」与 `GetNodeServices` 的「接驳服务」分组；事件标题读取 `EventTitle`，被注视 3 层时回视处置优先。`VoyageSupport.GetSupportChoices` 保留兼容的配装与事件接口；`IsLoadoutChoice` 限制船上清单仅查看／配装，购买、招聘、治疗、修械、营救邀请、筹备和回望均在主面板，经 `ManageSupport` 验证执行。服务不结算节点，也不能重开一次性节点收益；已结算节点隐藏服务，待邀请候选除外。`BattleSupplyPanel` 继续消费实际物资次数和目标，I14 封泥每场最多推进一次普通／雾海封线。

奖励页先选牌，再选择「直接编入（替换一张）」或「仅收入行动簿」。独立替换弹窗调用单次 `ClaimReward(id, oldId)`，Esc／右键／取消不修改状态；每次领取清空 UI 选择。`NewRewardCardIds` 只标记尚未整备的新收获，整备保存后清除。适用 Boss 标签读取目录 `BossIds`，在奖励选择、行动簿焦点／悬停摘要与提示中显示，不修改卡面、不把一般推荐等同于专用。险航徽记同时用于已公开航路和海图，普通预览读取 `PreviewStyle` 与公开候选通道，不反推锁定行动。

胜利先显示 `EncounterDebrief`，包含本场累计生命／理智承伤、实际消耗物资和去重后的可归档证据；承伤在威胁实际扣除资源时累计，排除主动支付、治疗和被抵御部分。`VoyageRuntime` 传入战斗计数，旧调用未提供计数时显示未记录，不推算净差。`DismissDebrief / DismissRegionIntro` 显式确认后才开放奖励／新海域输入；两种待确认状态进入检查点历史，减少动效仍完整显示。小结、替换牌组及行动簿均支持面板留白滚轮。

`VoyagePreparation` 提供 `PreparationBriefing / PreviewStop / PreviewShopItems / PreviewCrew`。未知航点拒绝访问，已知不可达航点仅返回历史摘要；商店按本幕实际 Boss 及本海域普通次目标筛选，幕末装备奖励按下一幕实际 Boss。候选先过滤已拥有项再定量，最后整备保证实际 Boss 筹备用品；预览不读敌方锁定意图。

`VoyageRituals` 经 `ManageSupport` 记录学习与筹备；`BattleLoadout.EchoRitual` 进入指纹。`BattleRitualRules` 使用 `Consume("ritual:echo", target)`，复用 C062 的合法召唤物目标与封缚，仅在验证后支付 3 理智、消耗一次筹备；不占物资份数。下一场结算时无论是否施放均失效。清单五页共用模态焦点锁、纵向滚动和四张无字情境底图；导入入口为 `Tools/SupportContentSetup.cs` 的 `ImportPreparationArt`。

证据以 `EvidenceScope` 区分回合、遭遇、本局、长期；`Stable` 只接受有对象类型和事实的 `source-v1`／`anchor-v1` 已验证关系。C042 普通战连接＋当前声源，或同类型旧档＋当前匹配声源，可通过 C048 得到本场来源；锚点验证记录铭牌、拓片及结果。存活目标与当前回合均重验。永久档案存储键为 v2，旧字符串不自动提升；航程战斗使用本局归档，永久见闻只供清单查看，不因跨局记录变化改变进行中的回放指纹。

Boss 自动公布召唤来源仅为 `Observed`，不能满足 C008／C090 的已验证条件；C046 首次追踪提升到 `Verified`，重复验证才抽牌。C052 仅对原已公开的守卫关系给予理智防护，C066 只牵引已验证匹配的守卫，不隐式验证；无匹配目标保留 5 格挡后备效果。C059 可取消当回合到期的 M04 警报脉冲，不取消普通攻击。C045／C071 的保留目标排除常驻遭遇牌。

C039／C041／C050 的调查接力共享每回合一次行动返还；C092 需要该目标两种不同调查牌新问题。工具／船员不计入这组问题。C091／C093 的可选保留复用 `PendingChoice` 与 `Reorder`，可显式跳过；等待时阻止其他命令。新卡资产同步和六张背景导入用 `Tools/SupportContentSetup.cs` 的 `Main`，不重建场景。
## 存档与复现

单场战斗回放格式当前为 **13**，包含完整内容 SHA-256、`bossKind`、初始种子和成功命令序列；Boss 类型、意图策略、船员费用与伤势、装备、物资、仪式、档案及实际初始资源进入指纹。恢复先验证版本与内容，再从头重放；新版本覆盖船员效果、循环随机起点与蓄势算法变更。旧回放不迁移，非法序列不替换当前会话。

数据指纹覆盖卡组顺序、全部卡牌效果、敌人意图、工具和战斗参数；任何内容改变都会拒绝加载旧回放。修改效果处理算法、随机算法、自定义目标或其他规则时必须提升 `BattleReplay.CurrentVersion`，旧版本迁移尚未提供。自定义注册表/目标的实现本身不进入数据指纹，版本升级是调用方契约。该机制用于本地复现，不是防作弊方案。

文件存储先写临时文件并 flush，再原子替换已有文件，保留旧 `.bak`；读失败不会自动覆盖或清空。默认实现面向桌面文件系统，WebGL/云存档需另实现 `IBattleSaveStore`。

航海用 `VoyageCheckpoint` 保存首幕地图、初始船员和成功命令历史，重建三幕路径、知识、奖励、配装、资源与阶段。地图版本 **9**、检查点版本 **14**；`Perilous` 进入地图校验，领奖替换通过 ClaimReward 历史的单个 `Values` 元素记录；多次收获、幕末已选海域未领奖、小结承伤与待确认过场均可重放。旧地图与旧检查点直接拒绝，不覆盖原文件，需明确开始新航程。

Editor 验收脚本 `Tools/UiExperienceQA.cs` 通过 `VoyageRuntime.BeginValidation` 将航程文件限定在项目 `Logs/UiExperience/`，验证会话不写永久证据偏好；真实战斗与命令规则保持不变。截图前实际调整 Game View，分别记录三比例原生像素与 UI 根尺寸。真实航程入口只通过合法命令推进，不直接设置胜利；结束时比较正式存档哈希并恢复减少动效偏好。

`Application.persistentDataPath/voyage.json` 使用版本 **1** 包装，组合航海检查点和可选的未结算 `BattleReplay`。每次成功局内操作保存回放；返回航海或标题后继续，恢复同一战斗状态，不重掷开场。胜负结算后清掉局内回放，进入奖励或失败；整局终结后归档到 `voyage-final.json`，主菜单不再提供继续该终局。结算或保存异常保留待结算数据和错误，可重试，不中断 HUD 的 `Changed` 通知。航行中恢复重播该段过场、不重复计段。文件原子替换并保留 `.bak`，旧格式或损坏文件明确报错，不自动覆盖；用户确认后仍可开始新航程。跨版本迁移尚未提供。
