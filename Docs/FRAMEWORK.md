# 基础框架开发指南

适用版本：Unity 6000.6.5f1 / URP。需求依据为 [概念设计](DESIGN_DOC_v0_1.md)。本文描述已实现的战斗基础、局外航海、扩展接口和存档契约；新增机制提案见 [机制与素材设计](ASSET_MECHANICS_DESIGN.md)。

## 快速运行

打开 `Assets/UnsoundedSea/Scenes/MainMenu.unity`，Play 后选择「启航」或「继续航程」进入 `Voyage.unity`；已有存档时新航程需确认覆盖。主页不再提供独立 Boss 快捷按钮，统一「调试选关」可选择 25 个普通遭遇、6 个 Boss/目标战及五海域的奖励、事件、档案、整备节点。Editor 运行当前场景；pull 不会自动切换入口。`Battle.unity` 保留为旧规则样例，`ModelImportReview.unity` / `EnemyRigReview.unity` 仅供美术审阅。

独立样例「雾海来客」：调查船上仅保留空潜水服「灯塔下的回声」，已移除蒙面祷告者。每回合 3 行动、抽 5 张牌；未选牌时点击敌人切换查看对象，选牌后点击敌人或脚下圆圈出牌，单敌人且目标唯一时直接出牌。调查工具每场次数有限。额外遭遇牌「绘制封线」消耗 1 行动，每回合一次，累计 4 段获胜；它保留在手，不进入普通牌堆，敌人可以仍然存活。生命或理智归零失败。航程将它用作第一幕目标战；普通节点使用各海域普通遭遇。独立样例允许重开，航程战斗只允许保存后返回航海、继续当前战斗，不提供重试刷新资源。

第二场「沉钟海域」：船与「沉钟之母」中心相距约 260 m；32 m 基础模型通过舞台锚点放大至约 208 m 总高，下部浸入海面。斜侧外部镜头完整呈现 18 m 调查船，巨兽占据远处右侧和上方，二者之间留出海面动作空间。每轮公开巨浪（21 生命伤害）或钟鸣（11 理智冲击，可打断）；用格挡、理智防护或打断应对，撑过五轮后撤离。进度在敌方结算后推进，资源归零优先判败；不提供封线行动，伤害 Boss 不代替生存目标。

## 航海选路（局外）

- **三幕标准航程（方案 A）**：海域仍为第一幕灰雾航道、第二幕尸骸之海／倒悬潮庭／无灯裂海三选一、第三幕无星深渊；Boss 不再与前两幕海域硬绑定。第一、二幕分别从共享七候选（雾海来客、沉钟、M02–M04、黑潮压舱者、空心航标）按主种子确定一个且不重复，第三幕固定 M05。每幕 11 层，一条完整航线实际访问 11 个节点（含出发整备和幕末 Boss），全局 33 个节点；分支候选不是额外必经节点。主种子派生拓扑、布局、Boss、内容、可见性和战斗种子；调查与动画不推进规则随机数。
- **分支与合并**：普通可分支层按 40%／42%／18% 采样一个／两个／三个出口，即 60% 分支、分支中 30% 三出口。起点固定两个出口、终点前一层固定一个、终点零出口；后续层宽度适应采样，不用补边改变概率。只连接相邻层，100×100 图坐标上横向差不超过 34、直线距离不超过 40。
- **节点节奏**：整备出发 → 普通战 → 事件 → 普通战 → 奖励 → 整备 → 普通战 → 档案事件 → 普通战 → 整备 → Boss。每幕四场普通战、一场目标战；战后另有奖励，不占额外航图节点。地点仍只使用漂流船、母船、救生艇、浮台、浮标和海况观测点，不登陆陆地。
- **知识边界**：开局只知道当前位置与两个出口，抵达后默认揭示最多两个后续出口，让已有分支直接可选；三出口节点保留第三条给旧海图，提前侦察保留。HUD 只读取 `KnownStops / KnownRoutes / Choices`，连节点的 `Next` 也过滤未知连接；不画隐藏地点灰点或完整拓扑。v6 地图与检查点不迁移 v5；Boss 简报按本幕实际遭遇生成，不按海域名猜测。
- **航行工具**：旧海图、测绘望远镜各每幕两次，分别补齐当前未知出口、侦察选定目的地再往前一段。无新信息或状态不允许时不扣次数；不占战斗槽、不因进入战斗刷新、不改地图与遭遇。
- **交互与动效**：默认中央为海面，右下航路列表显示地点、方向与耗时；选中后显示征兆和启航按钮，选择只预览，确认才出航。旧海图与远望收在海图下方，以文字和余次呈现；右上角文字按钮直接显示 M 海图、J 日志、B 行动簿、Esc 菜单，快捷键在根节点捕获，焦点位于按钮或滚动内容时仍可用，弹窗与文本输入保留各自限制。保留破损装饰字体，移除底部罗盘、航向针、圆形工具、启航印记与重复状态小字；累计小时和航段只在展开海图时显示。航图使用海流底纹、地点符号与弯曲虚线航路，不画隐藏拓扑；节点层间距以加长画布呈现，原生纵向 ScrollView 只滚动航图内容，打开时定位到当前航点，标题、图例、航行工具和关闭控件留在固定区域。调查船按所选目的地沿曲线实际转向、加速和减速；镜头从后斜侧跟随，滞后平滑转向且不随船体横滚。每段约 5 秒：前段出发地隐入浓雾，最后 2 秒目的地逐渐显现，抵达保留新位置与地点场景。减少动效改为约 0.25 秒淡化，在完全遮蔽时定位到终点；也支持途中开启。航行时收图；暂停／日志／设置冻结航段、海浪、船体、镜头和反射，展开海图也冻结环境，抵达只结算一次。
- **奖励与构筑**：新局从 12 张不重复行动开始；普通战后三选一、独立奖励节点四选一。幕末先选下一海域，再从公共／下一海域牌池三选一，领取后换幕；第三幕胜利直接结算。只投放未学方案，可放弃换 1 补给（上限 8），不提供刷新。候选卡牌居中排列，上方不加说明，下方留间距放置放弃按钮；奖励页不显示行动簿。奖励先进入本局行动库，不自动塞进牌堆。在每幕出发与整备节点编入恰好 12 张不同牌，并从提灯／听筒／贝壳中装备至多两件；其余节点的右上角行动簿只读。航程行动簿以窄左栏集中调查工具及保存／取消，宽右栏滚动展示大间距卡牌，计数仅显示 `12/12`；可编辑且选择合法时支持 S 保存。战斗行动簿沿用同样两栏，在左栏只读列出当前携带工具与返回、右栏显示当前构筑及 `12/12`，不提供伪编辑入口。标题全卡自由配装只用于独立遭遇。
- **事件、信息与资源**：开局生命 60、理智 30、补给 3；跨战斗保留实际资源，治疗上限 60／30。事件按种子选择拆取物资、拖回浮箱、检查锚链三类选项，显示资源或时间代价，可无损离开。档案可抄录当前位置全部后续航路、研读本幕实际 Boss 的真实操作规则，或封存恢复理智；简报写入 `Knowledge`，日志单独展示，重放恢复且跨幕保留，不提前揭露战斗随机答案。整备可免费小幅休整或消耗补给针对性治疗。节点只结算一次；船员沿用开局选定的医护员／听测员，本局暂不招聘。医护员每场一次、消耗 1 行动恢复 2 生命；听测员每场一次、消耗 2 行动取得声源证据；两者共享每回合一次船员支援限制。
- **决策反馈与历史**：治疗不按节点 ID 隐藏服务，只检查资源并显示禁用原因；没有新航路时禁止消耗节点抄录或标记。奖励领取后提示加入行动库，补给已满时放弃按钮显示“补给已满”，不承诺额外收益。相同整备配置不写历史，连续牌组／工具调整和航向预览合并为最终选择；出航、侦察或节点结算形成历史边界。Boss 分配与规则变化将航程地图／检查点升至 v6、战斗回放升至 v5，旧版本明确拒绝恢复。
- **战斗边界**：`VoyageEncounterCatalog` 按节点 ID 解析 25 个普通遭遇和八场 Boss／目标战；同幕四场普通战不重复主敌人，每海域第五种为双目标组合。黑潮压舱者复用沉钟海景和生存规则，公开 18 生命或 9 理智威胁并撑过五轮；空心航标复用回声模型与甲板舞台，本体 48 生命，公开 10 生命或 5 理智威胁，可直接击破；两者所有行动均可打断。普通战复用甲板舞台，但使用各自独立的静态角色模型；骨骼动画暂不接入。`Assets/UnsoundedSea/Editor/Tools/VoyageCampaignSetup.cs` 的 `Setup` 调用 `OrdinaryEnemyStaticSetup` 后同步普通遭遇、两场新增 Boss、回声强化和完整 Resources 目录，不重建场景。`CardDeckPreparation.Apply` 注入本局卡组、工具、船员和剩余资源；Director 成功命令保存战斗回放，胜负只回传一次。战斗内海图只读，关闭后恢复先前暂停状态。
- **调试边界**：`VoyageSession.CreateDebug` 创建独立内存航点，禁止 `Export`；`VoyageRuntime.StartDebugEncounter / StartDebugNode` 复用真实战斗或航海 UI，`Checkpoint` 不写正式存档，胜利也不写永久证据档案。进入调试前若正式战斗有未保存进度，必须先成功保存；失败时保留原会话与错误，不能清空待保存记录。普通调试战仍有三选一结算，Boss 调试战直接结束，返回标题后可继续原正式航程。目录包含全部八场 Boss；`storm-gauntlet` 与 `hollow-beacon` 是新增规则通关入口，任意正常航程种子用于验证前两幕不重复分配。

`VoyageMapGenerator`／`VoyageSession` 属于纯 C# 航海规则；`VoyageRuntime` 负责场景边界与文件；`VoyageHud`／`VoyageSailingPresentation` 只负责交互和航行表现。`Voyage.unity` 已使用调查船与 Uber 海面，场景组合位于 `Art/Voyage/VoyageSeaStage.prefab`：嵌套引用 `SurveyVessel.prefab`，复用海面网格、天空和调色；独立 `VoyageOcean.mat` 降低常态浪强度，不传入巨兽扰流。船体采样同一 `BattleWater` 波形，限制俯仰／横滚；`VoyageWake` 在世界坐标保留弯曲尾流，并随波形更新、逐渐消散。

`VoyageSailingPath` 将已知图坐标按 3 m／单位映射到局部海域（北 = +Z），用上一段航向作为出发切线；这是航程过场，不是小时数对应的真实里程或自由驾驶。每幕保持相同局部坐标范围，换幕重定位到新起点，不沿三幕累加世界距离。扩展地图尺度时须同步扩展海面或加入浮动原点。`VoyageSailingPresentation` 的船、水、相机和偏移均可替换；运行时拥有材质实例、反射与尾流网格，切场景时释放。`Tools/VoyageOceanSetup.cs` 的 `Apply` 可经 Unity CLI 重建这一组合，拒绝 Play／未保存场景；它会覆盖航行表现 Prefab 与材质，已有手调先检查 diff。地点组合由独立的 `Tools/VoyageNodeSetup.cs` / `Build` 维护；不需要重建海面，尚无靠泊或登船动画。

`VoyageDestinationPresentation` 只实例化当前位置及确认出航后的目的地，按地点名查 `Art/Voyage/Nodes/VoyageScenes.asset`，不按战斗／事件类型猜外观，不读取隐藏拓扑。新增或改名地点须同步目录映射，漏配会告警。每项可单独换 Prefab、相对抵达航向的摆放与朝向。`VoyageSceneView` 控制整组渐显、灯光和浮动部件；材质使用 `Voyage Landmark` Shader 的雾色及细粒度覆盖渐变，读取 glTF RGB 法线。前 3 秒目的地不可见，后 2 秒从轮廓到完整材质；暂停冻结雾与节点，减少动效在遮罩内切换。退出时清理实例并恢复场景雾值。

漂浮残骸仅用于货船、渔船和潮流观测点，分别 3／4／9 组；采用非对称断口与不同宽厚、长短、倾角，在局部成组布置，保留空水面。碎片采样同一海浪的水平位移与升沉；暂停、减少动效均冻结。`RefineDebris` 仅重建这五个相关地点（含清空残骸的救生艇和浮标），并清理其废弃网格。

这是 14 种地点表现，不是 14 个独立战斗关卡。两个新增 Rodin 模型与复用船体、Editor 制作的设施组成场景，来源与预算见 [节点资产 manifest](../ArtSource/Landmarks/manifest.json)。

当前是可完成的三幕航程闭环，25 种普通敌人已使用独立静态模型；不等于全部扩展系统交付。25 道具库存、装备被动、船员招聘、候选独立剧情、正式骨骼动画与五海域专属环境美术仍未完成。

## 3D 战斗组合与扩展

```text
BattleScenario（遭遇 + 场景 Prefab + 角色覆写 + 规则模块）
    → BattleDirector（独立 Session、选敌、命令、反馈锁、重开）
        → OceanBattleHud（BattleView → UI；Command → Director）
        → BattleStage（船体、相机、灯光、海面、音响、生成锚点）
            → BattleActorView（模型实例、碰撞选敌、名牌锚点、静态网格反馈）
```

- **换场景**：复制或创建带 `BattleStage` 的 Prefab，配置 `battleCamera`、`vessel`（所有随船运动的物体父节点）、`actorAnchors` 和选中材质，再替换 Scenario 的 `stagePrefab`。海面与音响可选；当前舞台不支持角色移动/导航。
- **镜头构图**：海面 Boss 的相机独立于船体 rig，船体摇晃不带动镜头；位置 `(85,22,-26)`、看向 `(0,8,70)`、垂直 FOV 60°。换船或海怪后需一起检查尺度、距离、海面覆盖、名牌和 HUD 遮挡，不能只移动相机。
- **甲板 / 海面锚点**：普通锚点保持甲板表现；海面锚点挂 `BattleAnchor` 并设为 `Sea`，必须放在船体 rig 之外，校验会拒绝错误挂载。设置独立位置、浸没深度、名牌高度/偏移、轻微升沉与扰流半径；海面角色通常关闭脚底选中环。碰撞范围按模型局部包围盒计算，锚点旋转/缩放不重复放大范围。
- **换角色**：修改 Enemy 的 `presentationPrefab`，或在 Scenario 的 `actorOverrides` 按敌人槽位覆写。模型约定脚底 y=0、正面 +Z、真实米制；锚点决定位置和朝向。同种敌人可以重复引用，规则实例 ID 为 `id:槽位`。出生前校验相机、船体、锚点和模型引用。
- **换遭遇**：Scenario 指向另一个 Encounter；牌组、资源、敌人意图和工具仍属于规则数据。UI 按快照更新，不依赖两只敌人的名字。新增敌人需增加相应舞台锚点并检查名牌排布。
- **特殊战入口**：派生 `BattleRuleModule`，为每次会话创建新的 `EffectRegistry` / `IEncounterObjective`。`SealingRuleModule` 用于雾海封线；`SurvivalRuleModule` 用于海面撤离，按已结算轮数计数。两者均不靠敌人全部死亡判胜。模块资产只存配置，不能共享可变进度。需要新命令、敌人阶段策略或即时玩法时仍需扩展 Core 与测试；当前入口不等于这些玩法已实现。
- **反馈事件**：Director 的 `Resolved(before, after, command)` 通知舞台，`Changed` 通知 UI；短暂反馈期间拒绝连点，规则仍同步确定性结算。暂停冻结舞台运动与环境声；减少动效关闭船体摇晃、镜头震动和角色摆动。

「沉钟海域」使用 **Uber Stylized Water**：多向不规则涌浪、细波法线、半分辨率破碎倒影、浪尖/接触泡沫和海雾；深海材质关闭折射与岸边透明渐隐，浅深色均为不透明；甲板战保留原轻量水面。巨兽扰流与钟声只负责表现，不影响规则随机数。场景雾、月光、暖色船灯、Bloom/Vignette 构成海洋氛围；音轨为原创合成底噪和动作提示。三名角色仍是无骨骼静态网格；海面战关闭占位攻击/受击位移和镜头震动，仅保留常态运动、音效与结算提示，正式动作等待骨骼动画接入。`BattleStage.placeholderCombatMotion` 控制占位动作和对应输入等待时长，甲板样例保留原表现。

### 海面配置

- `BattleStage.water` 可选接入 `BattleWater`，`surface` 指向同一海面 Renderer；使用 `Art/SeaBoss/DeepOcean.mat` 和 `DeepOceanMesh.asset`。水面保持水平、单位缩放，放在 Water（4）层，反射层排除水面；一场战斗只启用一个平面反射水体。当前网格为固定战斗镜头设计，不是无限海洋。
- `BattleWater` 在每场开始克隆材质并创建反射组件，停用时恢复原材质、清理相机和 RT。`_SeaTime` 驱动全部水面动画，暂停冻结时钟及反射；减少动效时以 1/4 速率连续推进，不跳变相位。`_Threat` 保留海面角色的扰流和冲击反馈。避免直接修改共享材质。
- 常态海况由两组基础波与四组方向、尺度、速度各异的相位扰动涌浪组成；浪尖按噪声破碎，巨兽周围持续产生宽范围不对称扰流。`DeepOcean.mat` 的 Storm 参数可在材质 Inspector 调整，修改后重开战斗刷新船体采样。`vesselFollowsWater` 使用同一组波参数、扰流和 `SeaTime` 驱动升沉/横移，船首尾与左右采样决定姿态，默认俯仰限 6°、横摇限 9°。换船后调整 `vesselSampleExtents`；这是平滑表现采样，尚非刚体浮力。暂停冻结海浪和船，减少动效保持船姿态，恢复时平滑追随。
- `BattleWaterLighting.hlsl` 以水的约 2% 正入射反射率计算 GGX 高光，读取主光/Forward+ 点光的颜色、强度、衰减与阴影；法线像素方差抑制远处闪点。`Specular Tint` 为 0–1 色调，`Roughness` 控制展宽（有效 0.22–0.8），旧 Hardness/Size 不再使用。浪尖泡沫使用 `SurfFoam Color` 作为漫反射色覆盖水面，接受环境与直接光，不作自发光相加；接触泡沫仍为低亮度美术色。
- PC 管线需要 **Depth Texture / Opaque Texture**；当前 Unity 6000.6.5f1、URP 17.6、Forward+ 已配置。`reflectionScale` 默认 0.5，降低可减少额外渲染成本。移动管线、XR、多相机/多水位组合尚未验收。
- 上游版本、MIT 许可、原始哈希与本地补丁集中记录在 [UPSTREAM.json](../Assets/ThirdParty/UberStylizedWater/UPSTREAM.json)。只引入运行依赖，不依赖上游 Shader Graph 编辑插件。升级需重新应用时钟、风暴波形/法线/泡沫、光照、扰流和反射补丁，并验证所有 Shader pass；不要用上游重新导出的 Shader 直接覆盖本地版。

`OceanBattlePanel` 参考 1600×900；USS 位于 `Runtime/Battle/OceanBattleHud.uss`。中央保留 3D 画面，局内不显示章节与地点标题。左下显示生命／理智，格挡与防护仅在生效时显示；调查工具列于上方并保留余次／费用。左上显示目标进度，右下集中回合、行动与结束回合；结束回合为圆形控件，文字独立放在圆下方，两套 HUD 一致。右上常驻无边框「海图 / M」与「行动簿 / B」，J 打开日志。牌库／弃牌／消耗数量收进日志；Boss 特殊行动使用额外遭遇牌，不提供重复的任务按钮。字体使用项目 TextCore SDF，保留破损装饰字体与旧铜色细线。

手牌默认约一半藏于下沿，常态右牌覆盖左牌；`HandCardPresentation` 将选中牌置顶，悬停／聚焦牌再置于其上，同时抬起 150 像素、放大 10% 并摆正。离开预览后恢复选中牌优先，其余牌恢复原始顺序。按钮命中区域稳定，显式 tabIndex 保持键盘顺序；多牌横向滚动随聚焦定位，不改变纵向隐藏量。不可用牌仍可查看精确规则、费用与消耗标记。实际新增手牌短促滑入／淡入，成功出牌显示牌名反馈；普通重绘不重复抽牌动画，减少动效关闭位移和淡入。

多敌人时，选牌后亮起合法敌人已有的脚下圆圈，点击敌人模型、信息区或圈内区域对该敌人出牌，不增加文字选框或操作说明；未选牌时点击敌人才切换查看对象。单敌人且合法敌人目标唯一时，点击卡牌直接使用。至多双目标牌先选一名，再选另一名结算双目标，重复点已选目标则只作用于该敌人；第一步不支付，已选圈加粗。可按 Esc 或右键已选牌取消。手牌、弃牌和证据等非敌人选择保留列表；M05 先选守卫，再点对应航标。无脚下圆圈的海面角色与旧 `BattleHud` 使用无文字圆形目标控件。失败保留卡牌选择与错误提示。海图／行动簿／暂停／结算弹窗禁用底层控件及根节点焦点，键盘留在当前弹窗；全局快捷键由根节点捕获，不依赖手牌或按钮焦点。

敌人信息按战斗相机视口和 UI 根节点换算，不依赖反射渲染期间的 `Screen` 尺寸；普通双敌按屏幕左右位置，将姓名、生命与意图分别放在两侧外缘，避开模型，以无边框 UI 同时显示。单敌信息放在左侧；Boss 本体与封线目标战放在上方中央偏左的留白区域，召唤单位保留左侧列表，避开右侧巨型本体及左侧机关区。共享 `EnemyIntentDetails` 将征兆按分号换行，省去“可能行动”等标题，生命伤害与理智冲击使用心脏／眼睛图标；未确认的多候选仍显示全部可能行为，不提前泄露真实分支。仅有一个可能意图的敌人从锁定起即视为已确认，条件伤害、抽牌与已确认目标规则共享这一状态。历史调查按需查日志。


`MainMenu` 与 `SettingsPanel` 共用深墨绿、旧黄铜与象牙文字样式；`SeaUiArt` 程序绘制罗盘、器物和异教印记，菜单不再使用网页卡片分栏。Esc 打开居中的窄幅暂停菜单，只显示短操作名称，与 J 航海日志分开；设置中 Esc 返回暂停菜单。覆盖存档警告、放弃后果和错误不省略。设置只保留音量、显示、垂直同步、动效标签与控件。航海界面移除常驻种子和教学段落，工具显示名称与次数，详细用途移至提示；海图与日志按需展开。`GameSettings` 属于设备偏好，不进入规则或回放。旧 `BattleHud` 同步扇形牌、仪表与意图排版，仅服务 `Battle.unity`。

场景已入库，无需生成脚本才能运行。需要有意重建本场样例时，用 Unity CLI 执行 `Tools/OceanBattleSetup.cs` 的 `OceanBattleSetup.Build`；它会覆盖本场场景与配置，但保留航海标题入口，运行前先保存改动。`Tools/SeaBossSetup.cs` 的 `ImportModel` / `Build` 分别归一化 Boss 并重建海面样例；仅重设海面战构图可调用 `SeaBossSetup.ApplyComposition`，不会重建遭遇或场景。重建后再执行 `Tools/UberWaterSetup.cs` 的 `UberWaterSetup.Build` 恢复新版海面（只更新水体、雾和相应 Prefab 配置）。`Tools/ImportSurveyVessel.cs` 负责选定船体版本的归一化；模型制作和 LFS 规范见 [模型全流程](MODEL_IMPORT_WORKFLOW.md)。

### 八场 Boss／目标战

M02–M05、雾海来客、沉钟、黑潮压舱者与空心航标均由主菜单「调试选关」调用目录中的同一 Scenario。前两幕从除 M05 外的七候选按种子选取且不重复，第三幕固定 M05；海域选择只影响普通遭遇与奖励池，不再决定 Boss。M02–M05 每场使用独立 Encounter 和舞台 Prefab；机制设计主出处为 [扩展设计](CONTENT_EXPANSION_DESIGN.md#b02b05-共用遭遇牌契约)。

- `BossRuleModule.bossKind` 选择 `BossEncounterKind`；`BattleScenario.CreateSession` 注入 Core 的 `BossEncounterRules`，每次重开创建独立状态。M02 为唱序封匣／击破发声囊，M03 为盐格封栓，M04 为继电器／闸锁／输出窗口，M05 为牵引守卫／关闭航标／撤离。
- 首回合正常抽牌后授予稳定实例的遭遇牌；保留在手、不进入普通牌堆，阶段和每回合次数通过 `CardView.Enabled / DisabledReason / Targets` 公开。出牌仍使用 `BattleCommand.Play`；无目标的聆听立即执行，其余选牌后选择目标，确认前不扣费，Esc／右键取消。
- 封线目标复用相同遭遇牌机制：`E01-01`「绘制封线」保留在手，基础费用 3 行动，费用支持既有场景折扣，每回合只能成功一次，回放记录为 `PlayCard`。回声强化为明确预告、可打断的 20 生命／10 理智二选一压力；连续三次同通道威胁会耗尽满资源，必须按预告插入防护或打断回合，不能只封线稳定取胜。旧 `AdvanceObjective` 命令仍供同版本检查点恢复，不再由 HUD 按钮发出。
- `BattleView.EncounterTargets` 只含公开机关状态；盐格危险位置不直接暴露。`EnemyView.Targetable` 区分可攻击单位和规则本体。召唤槽位休眠时隐藏模型，入场时恢复；M05 公开召唤顺序、下一次召唤与余响。
- `BossTargetAnchor` 连接场景机关与 HUD。M03 使用可读的 4×4 盐格盘；M04 只在选牌后展示对应极性／闸锁目标；M05 选定守卫后显示其航标。没有绕过遭遇牌的额外机关操作栏。

四个舞台复制共享 `DrownedBellStage`，直接继承沉钟的远景相机、Uber 水面、调查船与同相位随浪运动。四个本体均使用独立海面锚点与巨型世界尺度，调查船保持原尺寸作为对照；M04 不再作为船上小型人形 Boss，只有召唤物和机关留在甲板。名牌偏离主体轮廓，甲板单位的目标条分开排列，唱诗匣标签扩大间距，避免远景缩小后失去可操作性。`Tools/BossExpansionSetup.cs` 的 `ImportModels` 从归档 LOD0 导入并归一化，`Build` 重建四场配置、舞台、场景与构建列表；运行前退出 Play 并保存场景编辑。不会重建共享水面或航海场景。当前召唤单位复用现有角色模型，机关为可操作的基础几何道具；尺度记录与动画、性能状态见 [模型流程](MODEL_IMPORT_WORKFLOW.md)。


## 层级与依赖

```text
UnsoundedSea.Core                 纯 C#；无 UnityEngine 引用
    ↑
UnsoundedSea.Runtime              ScriptableObject、UI Toolkit、文件存档适配器
    ↑
UnsoundedSea.Editor               内容校验、幂等样例初始化

UnsoundedSea.Tests.EditMode       NUnit 行为测试，引用 Core / Runtime
```

规则层不读取场景、时间、全局随机数或静态单例。每个 `BattleSession` 独立持有牌堆、资源、敌人、知识和操作记录，可以同时运行多个会话。外部依赖通过构造函数注入，不引入服务定位器或全局事件总线。

- `Definitions.cs`：不可变战斗规格。构造时复制集合；Unity 资产只负责创作静态数据。
- `BattleSession`：命令入口、回合状态机及规则协调；所有玩家操作调用 `Execute`。
- `BattleView`：只读快照，UI 不持有可变规则状态。敌人的真实行动只存在于 Session 私有状态中。
- `CardCatalog` / `BattleCardRules`：90 张正式目录卡的规格、合法目标、费用与效果；`EffectRegistry` / `ICardEffectHandler` 保留通用效果和自定义遭遇扩展入口。
- `KnowledgeState`：证据带来源和可信级别，低级别记录不能覆盖已验证信息。
- `IEncounterObjective`：击退、封门、存活目标；可注入其他目标实现。
- `RunMap`：有向无环节点图，区分进入与完成节点，阻止跳点、回访、悬空连接和不可达节点。
- `BattleReplay` / `IBattleSaveStore`：规则回放与存储介质分离。
- `BattleDirector` / `BattleScenario`：运行时组合入口与可替换配置；`OceanBattleHud` 仅负责表现。

## 保证的规则

1. `TurnStart → IntentLocked → PlayerTurn → Resolve → TurnEnd`；终局进入 `Victory / Defeat` 后拒绝新操作。
2. 每回合重置行动、格挡和理智防护，默认抽 5、行动 3。手牌在结束回合进入弃牌堆；抽牌堆耗尽才洗入弃牌堆。
3. 卡牌拥有唯一实例 ID。出牌期间先离开手牌，效果结算后才进弃牌/消耗区，因此抽牌效果不能立即抽回自身。
4. 先验证费用、目标和可用性，再修改状态；失败命令不写入回放。效果处理器是受信任规则代码，应保持确定性、无异常、无外部 IO；目前没有针对自定义处理器异常的事务回滚。
5. 敌人行动在玩家回合前锁定。抽牌与敌方行动使用分离的固定算法随机序列；调查不访问随机数。两候选异常敌人共享征兆，而调查仅修改可见知识。
6. 提灯确认可观察动作；听筒只回答声源；贝壳只回答伤害资源类型。不可观察或已回答的问题不消耗道具。每场工具使用次数重置，最多装备两个不同道具。
7. 本回合意图确认在下回合失效；历史证据保留，键中包含目标和回合。日志只记录当时玩家可知信息，真实行动直到调查允许或实际结算时才显示。
8. 格挡仅减生命伤害，理智防护仅减被动冲击。主动支付绕过防护，并要求支付后至少剩 1 理智。耗尽生命或理智立即失败。
9. 封门任务独立于手牌，每回合最多一次、消耗 1 行动。击杀不自动完成封门/存活目标。存活目标在敌方结算后计数，资源耗尽优先失败。
10. `exhaust` 按实例计数；消耗牌本场不再洗回。C085 另有本回合同名限一次规则。保留按实例结算，到回合边界清除指定，不能让已打出的牌在后来洗回时继续保留。

## 新增内容

### 新卡牌

完整目录以 `Core/CardCatalog.cs` 为数据主出处，C001–C090 为稳定目录／效果号，既有十个内容 ID 保持不变。修改目录后通过 Unity CLI `run_script --file Tools/CardCatalogSetup.cs --entry CardCatalogSetup.Build` 同步 90 份 `Content/Cards/*.asset`、配置插画导入并校验；不会重建场景或替换既有 GUID。目录之外的遭遇卡仍可通过 **Create → Unsounded Sea → Card** 创建，使用通用效果或自定义处理器。

标题菜单图鉴只读浏览全部 90 张卡牌与完整卡面，不再编辑初始构筑。`CardCatalog.Starter` 是固定 12 张不同初始牌的唯一来源，旧自选牌组偏好不再读取；航程内仍可在整备点把已获得方案编入 12 张行动牌。`CardDeckPreparation` 只在游戏入口应用：主线 `BattleDirector` 调用 `CreateSession(..., usePreparedDeck: true)`，旧 `BattleHud` 显式应用；`EncounterDefinition.Build()` 保持纯内容构建，不读取玩家偏好。已验证战斗证据在胜利后归档，后续只注入对应敌人的档案。

90 张目录卡与 10 张 Boss／封线遭遇牌均有独立生成的 `Resources/CardArt/<稳定卡牌ID>.png` 背景，统一海洋哥特、旧黄铜暖光与冷蓝阴影。`IllustratedCard` 在主线、旧战斗 HUD 和行动簿复用：整幅插画铺满卡面，左上行动费用、牌名和完整规则均由 UI Toolkit 绘制；下半部中央叠加约 66% 不透明度的局部深色阴影，左右留 9、底部留 12 个界面像素，无横向分割，象牙色正文与旧金色牌名覆盖其上。额外代价和消耗只在规则正文写一次，不烘焙进图。菜单与操作按钮尽量单行，卡牌规则及日志保留必要换行。模型、提示词、来源与文件哈希集中在 [插画 manifest](../ArtSource/Cards/manifest.json)。

不可用卡牌不显示禁用原因；点击尝试出牌后，失败原因作为 2.5 秒字幕显示，右键／D 仍可查看完整卡面。遭遇牌费用只显示实际行动消耗，包括合法折扣；绘制封线基础消耗 3 行动。航程战胜利在动作反馈结束后自动返回航海，不弹胜利页；保存失败时留在战斗并提供重试保存，避免丢失结算。

滚动条统一复用 `GameMenu.uss` 的原生 ScrollView 样式：墨绿轨道、旧黄铜滑块和箭头、象牙色焦点；行动簿、航海日志及两套战斗 HUD 共用。保留原生滚轮、拖动、键盘和自动显隐，不替换滚动逻辑；行动簿详情宽度包含轨道留白，避免卡面产生多余横向滚动。

选目标统一使用 `CardView.Targets` 的稳定 ID；零选择牌传 `null`，失效选项在付款前拒绝。C054 先支付并打出，再通过 `BattleView.PendingChoice` 公开最多三张牌的完整排列；期间阻止其他命令，必须用 `BattleCommand.Reorder` 完成，零行动仍可选择，不能取消退款。两条命令均进入回放。C063 与 Boss 常驻继电器共享调整次数，C044 共享开格额度；其他场景的替代收益不绕过当前场景已有机制的次数或证据门槛。

通用扩展效果（目录卡另外注册 `c001`–`c090`，具体结算见 `BattleCardRules`）：

| ID | 参数与含义 |
| --- | --- |
| `damage` | 对所选敌人造成 amount 伤害 |
| `block` / `ward` | 获得 amount 格挡 / 理智防护 |
| `draw` / `heal` | 抽 amount 张 / 恢复 amount 生命 |
| `observe` | 记录可见征兆；amount 不使用 |
| `investigate` | 提灯式调查，意图已知则抽 1；amount 不使用 |
| `conditional-damage` | 已确认时造成 amount 伤害，否则 5 |
| `interrupt` | 打断本回合可中断动作；amount 不使用 |
| `objective` | 推进允许任务行动的目标 amount 点 |

新规则实现 `ICardEffectHandler`，在组合入口创建默认注册表后调用 `Register("your-effect", handler)`，传给 Session。处理器通过 `EffectContext` 执行动作，保持无状态、确定性；不要直接操作 Unity 对象。`conditional-damage` 的未知伤害 5 是当前样例规则；如需通用多参数效果，应扩展 `EffectSpec` 并同步内容指纹和版本，而非用卡牌 ID 分支。

### 新敌人和遭遇

创建 Enemy 和 Encounter 资产。意图的 `clue` 与 `candidateDescription` 必须提供可推断信息；不要在隐藏行动间意外使用泄露答案的 UI 图标。当前敌人从意图列表等概率选择；后续可提取 `IIntentPolicy` 支持循环、权重和阶段策略，始终在 `IntentLocked` 前决策。

同一敌人资产可在遭遇中多次引用，编译时按资产 ID 和下标生成不同实例 ID。`presentationPrefab` 是表现接入点；新 `BattleStage` 会实例化该字段或 Scenario 覆写。已绑定样例、独立审阅场景和生产流程见 [模型全流程](MODEL_IMPORT_WORKFLOW.md)。

自定义目标实现 `IEncounterObjective` 并注入 Session；恢复回放时必须注入同样的目标与效果注册表。当前资产菜单提供击退、封门和存活三种配置。

### 更换界面

生产 UI 可以使用 uGUI 或 UI Toolkit，只需读取 `session.View`，提交 `BattleCommand.Play / Investigate / Task / EndTurn` 并处理 `CommandResult`。不要从敌人配置和随机种子反推当前隐藏意图。快照会复制集合，适合按命令刷新，不应每帧轮询分配。

## 存档与复现

单场战斗回放格式当前为 **5**，包含完整内容 SHA-256、`bossKind`、初始种子和成功命令序列；Boss 类型、船员费用、初始剩余生命／理智及资源上限进入指纹。恢复先验证版本与内容，再从头确定性重放，重建手牌、弃牌、消耗、工具次数、知识、目标、Boss 阶段和回合。非法操作序列会拒绝恢复，不会替换当前会话；不迁移旧版本战斗回放。

数据指纹覆盖卡组顺序、全部卡牌效果、敌人意图、工具和战斗参数；任何内容改变都会拒绝加载旧回放。修改效果处理算法、随机算法、自定义目标或其他规则时必须提升 `BattleReplay.CurrentVersion`，旧版本迁移尚未提供。自定义注册表/目标的实现本身不进入数据指纹，版本升级是调用方契约。该机制用于本地复现，不是防作弊方案。

文件存储先写临时文件并 flush，再原子替换已有文件，保留旧 `.bak`；读失败不会自动覆盖或清空。默认实现面向桌面文件系统，WebGL/云存档需另实现 `IBattleSaveStore`。

航海使用 `VoyageCheckpoint` 保存首幕地图、初始船员和成功命令历史，重建三幕路径、知识、奖励、配装、资源与阶段；后续幕按种子和固定生成器版本派生。连续航向预览会压缩；回放仅在选路阶段接受对当前目的地的重复选择，以兼容调查前后改选产生的冗余历史。当前地图生成器版本 **6**、检查点格式 **6**；幕末选定海域但未领奖的状态也会恢复。第 5 版及更早航程不迁移，原文件保持不动，需明确开始新航程。

`Application.persistentDataPath/voyage.json` 使用版本 **1** 包装，组合航海检查点和可选的未结算 `BattleReplay`。每次成功局内操作保存回放；返回航海或标题后继续，恢复同一战斗状态，不重掷开场。胜负结算后清掉局内回放，进入奖励或失败。航行中恢复重播该段过场、不重复计段。文件原子替换并保留 `.bak`，旧格式或损坏文件明确报错，不自动覆盖；开始新航程须确认覆盖。跨版本迁移尚未提供。

## 验证与后续工作

Unity 菜单 **Unsounded Sea → Validate All Encounters** 可检查配置与未知效果；Test Runner 的 EditMode 中运行 `UnsoundedSea.Tests`。

使用已连接编辑器时：

```sh
export UNITY_PROJECT_PATH="$PWD" # 在仓库根目录执行
unity status --project-path "$UNITY_PROJECT_PATH" --format json
unity command run_tests --project-path "$UNITY_PROJECT_PATH" --timeout 180 --format json -- --mode editor --filter UnsoundedSea.Tests --timeout 120
```

CI 中关闭本项目的交互式 Editor 后：

```sh
unity test . --mode EditMode --filter UnsoundedSea.Tests --output Logs/framework-tests.xml --timeout 600
```

三幕航线、迷雾探索、奖励与行动簿构筑、事件选择、跨战斗资源和局内续战已接通。完整内容目标与尚未制作的库存、装备、招聘、独立事件及海域美术见 [内容扩展设计](CONTENT_EXPANSION_DESIGN.md)；继续复用当前航程与战斗模块，不另建第二套地图或协调器。
