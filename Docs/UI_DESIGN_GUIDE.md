# 《未测之海》UI 设计规范

本文是新增或修改界面时的统一规范，依据当前 [`GameMenu.uss`](../Assets/UnsoundedSea/Runtime/Presentation/GameMenu.uss)、[`OceanBattleHud.uss`](../Assets/UnsoundedSea/Runtime/Battle/OceanBattleHud.uss) 与 [`VoyageHud.uss`](../Assets/UnsoundedSea/Runtime/Presentation/VoyageHud.uss) 已采用的样式。界面的实现结构与接口见 [框架指南](FRAMEWORK.md)；理智显示与异常表现的规则边界见 [理智与船员设计](SANITY_AND_CREW_DESIGN.md)。

## 1. 总原则

1. **场景优先。**中央三维海面、船与怪物是画面主体；HUD 沿四周边缘排布，不铺满全屏数据面板。
2. **像游戏，不像网页。**用图标、数值、徽章、卡面与实体隐喻（印章、黄铜、羊皮纸）表达信息，少用说明句和表单式列表。
3. **只显示影响决策的信息。**设计说明、规则解释和开发术语不常驻界面；需要时放入悬停提示或日志。
4. **信息可信。**数值、费用、意图与日志不显示假值；表现疯狂时不移动按钮命中区、不篡改文字，见 [理智与船员设计 7.3](SANITY_AND_CREW_DESIGN.md#73-信息可信与视觉约束)。

## 2. 布局与适配

- 所有 UI Toolkit 面板采用「按屏幕尺寸缩放」，匹配值 0.5；战斗参考分辨率 1600×900，菜单与航程 1440×900。
- **禁止使用屏幕像素坐标。**位置只用面板单位的边距锚定（left／right／top／bottom）、百分比或 Flex 布局。
- 跟随三维物体的元素（名牌、机关标签、目标圈）：
  - 按战斗相机视口与 UI 根节点尺寸换算，不依赖 `Screen`；
  - 限制在屏幕内，四边至少留 12 面板单位；
  - 与其他标签重叠时自动错开。
- 战斗固定区域：

| 区域 | 内容 |
| --- | --- |
| 左上 | 目标进度、Boss 状态 |
| 右上 | 海图、行动簿等功能按钮 |
| 左下 | 工具与船员，其下为生命与理智 |
| 右下 | 牌堆计数、回合与行动、结束回合 |
| 底部中央 | 手牌（左右对称留白，间距随宽度自动收紧） |
| 中央上方 | 敌人或 Boss 名牌 |

- 必须验收的比例：16:9（1920×1080）、21:9（2560×1080）、4:3（1600×1200）。任何比例下不得重叠、裁切或滑出屏幕。
- 海图标题只保留「海域 · 海图」，幕数与航点进度统一由左上总信息展示，不另写已知海域说明。标题与底部状态图例不参与压缩，中间地图独立滚动；图例按完整的「标记＋短词」分组留白，窄屏允许整组换行。

## 3. 颜色

| 用途 | 色值 |
| --- | --- |
| 主文字（象牙白） | `#eee4c9` |
| 强调、焦点、标题装饰（黄铜） | `#d7bd82`；描边 `#9e8755` |
| 理智、已确认、增益（青绿） | `#80b5a5` |
| 生命、危险（锈红） | `#ac7566`；警示文字 `#f2bc9d` |
| 次要文字 | `#a9b6ad` |
| 面板底色 | `rgba(8,19,22,.82)`；弹窗底色 `rgb(15,31,35)` |
| 遮罩 | `rgba(1,8,13,.88–.96)` |

- 颜色不能单独承载含义，必须同时配图标、形状或文字；生命用心形，理智用眼形。
- 只有禁用状态降低透明度（0.4–0.45）；短暂的反馈锁定期间保持原透明度，不闪烁变灰。
- 含插画的阅读面板在插画与文字之间加深色遮罩，正文使用近不透明的阅读底层；插画只保留气氛，不能让文字直接叠在高细节图案上。

## 4. 文字

- 所有界面通过 `UiFont` 使用同一套中文 SDF 字体，不各自引用字体资产。
- 字号阶梯（面板单位）：

| 层级 | 字号 |
| --- | --- |
| 大标题 | 27–30 |
| 弹窗或页面标题 | 22–28 |
| 主数值（生命、行动） | 19–23 |
| 正文、按钮 | 15–17 |
| 次要说明 | 13–14 |
| 标签、徽章 | 11–12，不得小于 10 |

- 文字规则：
  - 数值不带单位字「点」，由图标代表单位：写「♥ 8」，不写「8 点生命伤害」。
  - 按钮不写快捷键文字（如「海图 / M」），快捷键用键帽徽章表示，见第 6 节。
  - 不显示「（公开）」「聚焦 · XX」「D 详情」、节点副标题等面向设计者的标注。
  - 状态用短词：「已打断」，不写「已打断 · 本回合不行动」。
  - 清单以槽位、物品卡和短状态呈现；名称、数量与操作只出现一次，完整效果放在选中详情或悬停提示。档案按实际调查内容分组，不向玩家展示内部来源 ID、验证版本或接口说明。
  - 同一事物全游戏只用一个名字；海域统一为灰雾航道、尸骸之海、倒悬潮庭、无灯裂海、无星深渊。
  - 单行按钮和标签设为不换行（`white-space: nowrap`），并确认最长文案放得下；描述类文字可换行，但必须限定最大宽度。
  - 文字不得超出所在按钮或框的范围，验收截图时逐项检查。

## 5. 图标

- 统一使用 `SeaUiArt` 图案：heart、eye、ear、shield、scroll、compass、gun、shell、lantern、seal、bearing、tentacle。新图标先加入 `SeaUiArt`，不引入零散图片。
- 与数值同行的图标 20–26 面板单位；功能按钮图标 46–92。
- 含义固定：心 = 生命；眼 = 理智；盾 = 格挡或免伤；印章 = 结束回合与菜单标记。

## 6. 按钮与交互

- 按钮类型：
  - **主按钮**：黄铜描边、深色底，每屏最多一个（启航、领取、结束回合）。
  - **次按钮**：透明底，只有底边线，用于工具栏、暂停菜单。
  - **选项卡片**：左侧 2–3 单位黄铜竖线，标题加一行说明，用于节点选项、航路、奖励道具。
  - **实体按钮**：卡牌、船员卡、机关、结束回合印章；悬停上浮或放大，按下轻微缩小。
- 每个可点击元素都有常态、悬停、焦点、按下、禁用五种状态；焦点用象牙色描边，保证纯键盘可操作。
- 快捷键：用 `KeyBadge.Attach(按钮, "M")` 加键帽徽章，悬停提示写「名称（M）」。
- 点击区域至少 40×40 面板单位；相邻按钮间距至少 6。
- 禁用必须说明原因（悬停提示或副标题）。不可用就直接禁用，不允许点击后没有任何效果的陷阱。
- 禁用原因读取当前实际限制，如「战斗物资已满（2/2）」或「先卸下盐蚀怀表」；不把多个可能原因用「或」串联，让玩家自行猜测。
- 互斥的节点选项与不占节点结算的接驳服务分两组显示；可取消的操作同时支持 Esc、右键和「取消」按钮。

## 7. 战斗信息显示

- **敌人名牌**依次为：名字 → 血条（Boss 本体不可伤害时以盾形图标代替）→ 征兆（一句）→ 意图行。
- **意图行**：通道图标 + 行动名 + 大号数字，「可打断」等修饰显示为小标签。
  - 已确认本回合不攻击时不显示意图；候选中的不攻击行动只显示行动名，不显示图标和 0；召唤当回合不行动的单位不显示意图。
  - 蓄势层数、节奏／隐匿标签以小徽章挂在名字旁。
  - 本回合查到的声源、伤害通道直接显示在名牌上。
- **手牌**：平时露出上半张，悬停时整张抬起显示完整描述；牌多时自动收紧间距，不裁切。拖牌只在有目标时显示瞄准线，拖动中不显示操作提示文字。
- **资源**：生命与理智用条加数值；理智条在 12 和 5 处画刻度，标注「动摇／临界」。牌库、弃牌、消耗用三个计数小框，不放在手牌区域。

## 8. 弹窗与流程

- 弹窗下一律加遮罩，打开期间底层界面全部禁用；关闭后焦点回到打开它的元素。
- 有存档时「继续」排第一并默认选中；会覆盖存档的操作需要二次确认。
- 一个流程只做一件事：选船员、领奖励、替换牌各自一步完成，不在同一面板堆叠多个决定。
- 关键节点要有反馈：战后小结、换幕过场、领取成功提示；1–2 秒后自动消失或可跳过。

## 9. 动效

- 非卡牌动效时长 0.12–0.24 秒，统一缓出曲线（ease-out-cubic）。卡牌动画按用户要求保留既有实现，不随本方案改动悬停抬升、选中、拖放、入手和出牌动画。
- 动效只用于说明因果：出牌、受击、数值变化、抽牌；不做纯装饰循环。
- 「减少动效」关闭位移、旋转、闪烁和镜头抖动，但保留状态变化本身。
- 动效期间拒绝连点，但按钮不显示为禁用灰色。

## 10. 代码约定

- 样式只写在 `.uss`，C# 只添加 class，不写内联颜色或字号；跟随三维物体的元素可在代码中设置位置。
- 共用组件只有一个出处：键帽徽章 `KeyBadge`、敌人意图 `EnemyIntentDetails`、卡面 `IllustratedCard`、图标 `SeaUiArt`、字体 `UiFont`、共用样式 `GameMenu.uss`。
- 新增可交互元素必须有稳定的 `name`，便于测试和恢复焦点。

## 11. 验收清单

- [ ] 三种比例截图检查：没有重叠、文字溢出或滑出屏幕。
- [ ] 按钮上没有快捷键文字、单位字「点」、设计者标注或开发术语。
- [ ] 不攻击的敌人不显示意图；所有禁用按钮都说明原因。
- [ ] 纯键盘可完成整个流程，焦点始终可见。
- [ ] 「减少动效」开启后流程完整、信息不缺。
- [ ] Play 模式控制台没有报错。
